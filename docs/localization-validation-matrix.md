# 三語、外觀與裝置驗收矩陣

## 文件目的

本文件是跨功能的穩定驗收清單，不保存某一次 change 的日期、截圖或「已通過」聲明。單次實施證據應留在測試輸出、OpenSpec archive 或對應功能的發布記錄中；只有能長期約束後續實現的矩陣項才寫在這裡。

三語文案、外部資料與 TTS 規則見 `localization-guidelines.md`；UI／UX 原則與視覺規則見 `ui-style-guide.md`；模擬器所有權與適配規則以 `AGENTS.md` 為準。

## 基準維度

| 維度 | 必要覆蓋 |
| --- | --- |
| App 語言 | 香港繁體、簡體中文、English |
| 跟隨系統 | 英文、`zh-Hant`、`zh-Hans`、裸 `zh`、不支援 locale |
| 外觀 | 固定淺色、固定深色；跟隨系統的淺／深切換 |
| 螢幕 | 約 360dp portrait 的小屏手機是核心基準；另以至少一個常見較大手機尺寸檢查伸展 |
| Android | 目標 API 36；涉及兼容性時補最低支援 API 25，不以未配置的未來 API 作固定門檻 |
| 字體 | 全頁 font scale 1.0；高風險頁 1.3 與 2.0 |
| 導航／輸入 | 手勢導航與常見 IME；涉及舊系統兼容時補三按鍵導航與 API 25 IME |
| 狀態 | 初始、載入、成功、空、失敗、刷新、取消、Activity/Fragment 重建 |
| 無障礙 | TalkBack 名稱、焦點順序、狀態可辨識、核心 action 至少 48dp |

完整笛卡兒積成本過高時，至少保證每個核心畫面三語 × 淺／深 × font 1.0，並把長英文、小屏、font 2.0、IME、重建和錯誤狀態集中到表中標為高風險的場景。任何被省略的維度都要在交付摘要中明確列出，不能以本文件存在代替實際執行。

## 搜尋、IME 與捲動 ownership

- 新增、編輯、複製及臨時搜尋的起終點，在沒有動態狀態時只顯示緊湊 label／hint；搜尋中、無結果、失敗、定位、校驗與 Google attribution 必須跟隨所屬欄位並可正確清除。
- 臨時搜尋在 360dp、font 1.0 與常見 IME 下應顯示 5 至 6 個完整候選；空間不足或大字體時只減少完整項目數，不顯示半項，也不為湊數改用更大螢幕。
- 候選列表打開後獨佔垂直手勢；到頂或到底都不能把剩餘手勢交給 AppBar、頁面、結果列表或下拉刷新。關閉後恢復原本的滾動及刷新資格。
- 頂層 `MainActivity` 的底部導航保持在物理底部，由 IME 覆蓋時不可觸控、不可取得無障礙焦點；收起 IME 後 destination、量度與位置不變。
- 常用與搜尋的頂部輸入／快捷區不直接驅動 AppBar。只有有效結果列表的 nested scroll 可以收折或恢復頂部；候選列表、空狀態與編輯器各自保有清楚的滾動 ownership。
- 查詢中的按鈕、IME action 與下拉刷新不得重複提交；取消、舊刷新與過期 callback 不得覆寫更新的查詢。

## 臨時搜尋結果保留

- 非空成功結果把輸入器折疊為輕量 `起點 → 終點` 上下文欄；鉛筆和保存 action 均至少 48dp。
- 360dp、正常字體的長地點可單行尾部省略；font 1.3／2.0 可改為兩列，但操作不縮字、不裁切。
- 點擊鉛筆以約 240ms 的高度變化和淡化替換為完整編輯器，不自動聚焦或彈出 IME。
- 編輯中的新文字不清除上一次成功結果；詳情與監控繼續使用上一次成功查詢快照。只有提交新查詢才清除舊結果；空或失敗保持編輯器。
- 新查詢成功後才建立保存資格；修改、清除或交換地點後，舊結果不可被保存為新的起終點組合。

## 動態資料與併發

- 每種 App 語言都以真實 Citybus 地點搜尋、P2P 路線、`showstops2`、`getp2pstopinroute` 及 DATA.GOV.HK ETA 驗證至少一個直達樣本；換乘或分段步行變更時補兩段樣本及 matching／missing session 對照。
- Google 目前位置地址必須以可用真實 API key 驗證三語；路線地圖變更時亦須以真實 Maps SDK 圖磚及 `getlinep2p` 道路幾何驗證直達、換乘與高縮放端點。mock、fixture 或網絡逾時不能代替這些硬門檻。
- Google 底圖內建標籤可依 Google／裝置環境，不據此判定 App 本地化失敗；App 自有摘要、marker title、錯誤、地圖控件、通知健康與系統設定引導仍逐語驗證。
- geometry 局部失敗只移除失敗巴士段，不畫站點假直線；Maps、位置或 ETA 各自失敗時，文字時間線、其他成功段和返回操作保持可用。
- 驗證單欄位語言回退、整體請求失敗不跨語言重試，以及語言切換後舊 callback 不覆寫新畫面。
- 快速連續搜尋、交換、刷新、切換頁面、切換語言與重建時，cache key、generation 與 query snapshot 不得交叉污染。
- 外部服務局部失敗時，已取得的基礎路線仍可展示；站點預覽與 ETA 各自降級，不互相阻塞。

## 監控系統能力驗收

- 分別覆蓋 App 通知關閉、正常頻道停用、緊急頻道停用／降級、鎖屏隱藏及平台不可判定；只有阻斷狀態禁止啟動，警告／未知須以對應語言說明後允許基本監控。
- 驗證精確頻道設定 → App 通知設定 → App 詳情 → 手動引導的 fallback，並在每次返回 App 後重新讀取健康狀態。
- Android 12+ 覆蓋精確鬧鐘已授權、拒絕與設定不可用；覆蓋電池最佳化已豁免、同意、稍後、拒絕及 Intent 不可用。非通知阻斷能力不得造成啟動循環或永久卡住。
- 360dp、三語、淺／深、font scale 1.0／1.3／2.0 下，設定內容可捲動、固定主要 action 可達、`−／+` 每次改變一分鐘，速度／場景重算後保留正負手動偏移。

## 更新檢查驗收

- 自動檢查未滿 24 小時不訪問 Play 或網站；手動檢查繞過節流。
- 已有檢查進行中時附著同一工作，不建立第二組 provider 請求。
- Debug 在讀取 installer、Play package、Play Core 或網站前短路。
- Play 有更新時，網站 metadata 只在 versionCode 精確一致時補 versionName；不一致或失敗仍顯示可靠的通用更新，不以 versionCode 假冒版本名。
- Play 無更新不訪問網站；`ERROR_APP_NOT_OWNED` 只有網站較高 versionCode 才形成正向更新；Play 臨時失敗不訪問網站且保留既有可靠快照。
- 真實 flexible update 只能由 Play 安裝、已擁有 App 的帳號與合適真實裝置驗證，不能以 adb 安裝或網站 APK 取代。

## 模擬器與設備使用約束

開始前先定義場景要求，例如 API、最小螢幕寬度、導航方式、Google Play／Google APIs、IME 與性能級別，再選擇設備。

- 只可使用本次任務自己啟動的 emulator／AVD；任何任務開始前已運行的設備都視為他人佔用，不連接、不操作、不停止。
- 合適 AVD 被佔用時等待其釋放，再由本次任務自行啟動；不得改用不符合場景的 AVD，例如用大屏替代小屏驗收。
- 沒有符合需求的 AVD 時停止該項驗證並報告缺口，不以降低 API、螢幕、Play 能力或導航要求宣稱通過。
- 驗證結束後關閉本次任務啟動的全部 emulator；實體設備亦需確認已獲本次任務使用授權。

## 自動化與交付記錄

最低自動化門檻包括：

- `LocaleResourceContractTest`、`JourneyRouteTerminologyContractTest` 與可見文案硬編碼掃描；
- provider language mapping、formatter、parser、cache、generation／stale callback 與 TTS Voice policy 測試；
- 受影響功能的定向 unit／instrumentation 測試；
- `./gradlew build`，若因外部環境未能執行，需在交付摘要列出原因與已完成替代驗證。

每次人工或 instrumentation 驗收記錄至少包含：App 語言、外觀、font scale、設備型號／AVD、API、螢幕尺寸、導航方式、IME、真實或 fixture 資料來源，以及未覆蓋項。永久文檔只保留可重用規則；某一批 change 的完成摘要依 `documentation-governance.md` 記錄新增、重寫、刪除、未改與剩餘缺口。
