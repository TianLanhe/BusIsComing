# 底部導航、搜尋輸入與首次空狀態優化設計

## 背景

BusIsComing 已拆分為「常用／搜尋／設定」三個頂層模組，並已支援三語、深淺色模式、Citybus 地點搜尋及 Google 目前位置地址解析。現有資訊架構合理，但仍有四類界面問題：底部導航只在點擊瞬間提供動畫，完成後的選中狀態不夠明確；搜尋頁的起終點欄位、交換按鈕及候選清單缺少一體化關係；搜尋結果排序與常用頁樣式不一致；首次沒有常用行程時，同時提供新增與臨時搜尋入口，削弱了「儲存常用行程」的核心價值。

本設計以局部一致性優化為範圍，不重做頂層導航、查詢流程或資料層。術語遵循「常用行程 -> 查詢 -> 多條路線」：用戶儲存的名稱、起點及終點稱為行程，Citybus 查詢返回的乘車方案稱為路線。

## 目標

- 讓底部導航在任何時刻都能清楚表達目前模組，而不只依賴點擊動畫。
- 把起點、終點及交換操作整理成緊湊且有路線順序感的輸入器。
- 讓候選、載入、無結果、錯誤及 Google attribution 明確歸屬於各自欄位。
- 讓搜尋結果排序與常用頁使用同一套視覺和狀態規則。
- 讓首次空狀態以建立常用行程為唯一主操作，同時保留底部搜尋入口。
- 在繁體、簡體、英文、深淺色、窄屏及大字體下保持可讀、穩定和可操作。

## 非目標

- 不調整「常用／搜尋／設定」三個頂層模組及其導航目的地。
- 不把搜尋頁擴展為新的地圖主導探索頁。
- 不重構 Citybus、Google、DATA.GOV.HK、SQLite、路線查詢或 ETA 資料流。
- 不把起終點輸入器抽成跨所有頁面的完整共用元件。
- 不改變新增常用行程、查詢路線、儲存為常用行程或結果排序的業務行為。

## 方案選擇

採用「聚焦界面一致性」方案：保留現有頁面及 Fragment 邊界，只調整相關 XML、樣式資源及少量 UI 狀態協調。共用 drawable、color selector、text appearance 及 button style，避免常用頁與搜尋頁再次產生樣式差異，但不進行大範圍元件重構。

未採用以下方案：

- 全面抽取共用輸入器與排序元件：一致性更強，但會擴大至已穩定的行程新增／編輯流程。
- 重做為地圖主導的搜尋探索頁：涉及地圖、候選及結果聯動，應作為獨立迭代處理。

## 1. 底部導航選中狀態

三個導航項保持等寬，導航欄在同一字體與裝置配置下保持穩定高度。切換選中項不得令導航欄或頁面內容上下跳動。

### 視覺規則

- 選中項持續顯示低對比度膠囊形 active indicator，而不是只在按下時顯示圓形漣漪。
- 選中圖示視覺尺寸為 `28dp`，未選中圖示為 `24dp`。使用固定 `28dp` 圖示槽配合 drawable inset 表達差異，避免切換時重新量度。
- 選中文字使用 `14sp` 粗體；未選中文字使用 `12sp` 常規字重。
- 選中與未選中項均保留圖示及文字，焦點順序不變。
- 點擊漣漪繼續表示按下回饋，active indicator 表示目前所在模組，兩者不可互相取代。
- 大字體配置可以令整個導航欄採用足夠的穩定高度，但不得按不同 Tab 的文字長度個別改變高度。

### 顏色與主題

淺色及深色使用相同幾何、字重和狀態層級，只切換語意色。深色模式使用深色表面、低飽和強調色 active indicator、高對比選中內容及較弱的未選中內容；不得只降低整個導航項透明度而令文字難以辨認。

## 2. 連體路線輸入器

搜尋頁的起點和終點改為一個視覺相連的輸入區。左側為上下排列的兩個地點欄位，右側保留固定寬度的交換操作區。輸入區不放入額外裝飾卡片。

### 基本版面

- 起點及終點欄位的基礎高度為 `56dp`，兩者以細分隔線和起終點標記建立順序感。
- 交換按鈕位於輸入欄位右側，觸控區為 `48dp x 48dp`，使用既有交換圖示和無障礙描述。
- 交換按鈕相對輸入器頂部使用固定位置，不因候選清單展開而上下跳動。
- 空白欄位的「起點／終點」使用 `16sp`；聚焦或已有內容後使用 `12sp` 浮動標籤，已選地點維持 `16sp`。
- helper 使用 `12sp`，只在欄位激活、需要輸入指引、無結果或錯誤時顯示，避免兩段常駐說明拉長表單。
- 起點的目前位置圖示保留。搜尋載入時暫時隱藏目前位置操作，並在同一尾端工具槽顯示小型進度狀態；完成後恢復目前位置操作，兩種狀態不得同時擠壓輸入文字。終點使用相同尺寸的尾端工具槽，確保兩個欄位的文字可用寬度一致。

### 候選清單歸屬

每個候選清單直接放在其輸入框下方，寬度只與左側輸入欄對齊，不延伸到交換按鈕下方：

- 起點候選插入起點與終點欄位之間，並把終點及後續內容向下推。
- 終點候選插入終點欄位下方，並把查詢按鈕及後續內容向下推。
- 同一時間只可展開一個候選清單；聚焦另一欄位時收起前一清單。
- 搜尋頁清單最多顯示三項，超出後在清單內滾動；IME 上沿和可見安全距離優先，實際空間不足時可以少於三項。此上限只適用於搜尋頁，不改變行程新增／編輯頁既有的 3–6 項自適應策略。
- 輸入器本身不得因載入文字或候選數量產生橫向位移。

### 欄位狀態

候選、載入、helper、無結果、錯誤及 attribution 均屬於單一欄位。新輸入必須取消舊搜尋回饋並令過期結果失效。選中候選後收起清單並清除不再適用的 helper 或錯誤。

Google 目前位置解析所需 attribution 不固定屬於起點，而是跟隨被 Google 解析的地點值：

- 使用目前位置建立起點時，在起點下方顯示 attribution。
- 交換起終點時，地點、未完成文字及 attribution 歸屬一起交換，之後 attribution 可顯示在終點下方。
- 用戶修改文字、選擇 Citybus 候選或清除該值時，移除對應 attribution。
- attribution 歸屬須納入 instance state，Activity／Fragment 重建後不得遺失或顯示到錯誤欄位。

## 3. 搜尋結果操作與排序

### 結果摘要和操作

結果摘要及更新時間保持在排序欄上方。「編輯」是次要文字操作；「儲存為常用行程」使用較明顯的 tonal 按鈕，表達搜尋後的主要延伸價值是把起終點儲存為可重複使用的行程，而不是保存某一條查詢路線。

緊湊寬度小於 `600dp`，或 font scale 大於等於 `1.3` 時，操作區固定移到摘要下方；寬度大於等於 `600dp` 且 font scale 小於 `1.3` 時，摘要與操作同列。按鈕使用 `wrap_content + minHeight 48dp`，不可因既有固定 `48dp` 高度裁切兩行文字。此適配使用現有 Android 版面能力，不新增第三方自動換行布局依賴。

### 排序一致性

搜尋與常用頁共用同一個 checkable button style 及狀態色：

- 每項 `minHeight 48dp`、水平內距 `14dp`、文字 `13sp`、相鄰間距 `8dp`。
- 選中項使用強調填充背景和高對比文字；未選中項使用普通表面、主要文字及分隔色描邊。
- 當前排序項顯示升序或降序箭頭，再次點擊切換方向；切換不得改變按鈕高度。
- 排序列可水平滾動，不縮小或裁切「路線／價格／耗時／候車／步行」及三語對應文字。
- 「路線」仍表示查詢結果，不能因已保存配置改稱行程而改為「行程排序」。

## 4. 首次空狀態

首次沒有任何常用行程時，常用頁繼續展示標題、靜態路線結果預覽和單一主操作：

- 標題使用「把常用行程放在這裡，出門前一按即查」及各語言自然對應文案。
- 預覽標籤由泛化的「示例預覽」改為「路線結果預覽」，明確表達卡片是保存行程後可快速查詢的路線結果。
- 預覽沿用現有靜態資料，不發起網絡請求；卡片不能進入詳情、查看 ETA 或啟動監控。
- 唯一主按鈕為「新增常用行程」，並沿用現有 `RouteEditActivity` 動線。
- 移除常用頁內的「搜尋路線」次按鈕及其 listener；`search_routes` 字串仍用於搜尋頁提交按鈕，不得一併刪除。
- 底部「搜尋」Tab 保持可見並作為一次性查詢入口。移除空狀態次按鈕不等於移除臨時查詢能力。

## 5. 元件及狀態邊界

- `BottomNavigationView` 繼續負責三個頂層目的地；選中視覺由 active indicator、文字樣式、狀態色和圖示 selector 完成。
- `SearchFragment` 負責組合輸入版面、交換操作、attribution 歸屬、結果摘要適配及排序狀態展示。
- 兩個 `PlaceInputController` 繼續各自負責文字監聽、debounce、候選、載入、錯誤、過期請求取消及選中地點；不把 HTTP 或解析邏輯移入 Fragment。
- attribution 是搜尋表單欄位狀態，不修改全域 `Place`、Citybus repository 或 Google repository 契約。`SearchFragment` 分別保存起點與終點的 Google attribution 布林狀態，並與欄位值一起交換及寫入 instance state。
- `PlaceInputController` 接受搜尋頁專用的最大可見候選項參數；預設值保持既有 3–6 項策略，搜尋頁傳入三項上限，避免改變行程新增／編輯頁行為。
- 排序行為仍由既有 `RouteQueryState` 和各頁控制器處理；共用 style 負責視覺，避免兩頁各自手動維護不同 stroke、背景及文字色。
- 首次預覽繼續使用 `FirstRunRoutePreview` 和禁用的 `BusRouteCardActions`，不建立假的可互動資料流。

## 6. 錯誤與恢復

- 關鍵字不足時收起候選和載入狀態，不顯示過期錯誤。
- 地點搜尋失敗時，錯誤只顯示在對應欄位下方；另一欄位及已選地點不受影響。
- 沒有候選時顯示欄位級無結果 helper，不建立空白候選面板。
- 聚焦切換、交換、文字修改、語言切換或 Fragment 銷毀時，沿用 generation／sequence 機制令舊 callback 失效。
- Google 反向地址解析失敗時沿用現有目前位置錯誤及手動選擇恢復路徑，不增加跨語言重試。
- 旋轉或系統重建後恢復起終點文字、已選 Place、排序、已提交查詢及 attribution 歸屬；不自動恢復已過期候選面板。
- 結果查詢、刷新、空結果及失敗狀態保持既有行為。

## 7. 本地化、無障礙與主題

- 新增或修改的 runtime 文案同步提供香港繁體、獨立審校的簡體及自然英文。
- 常用配置使用「常用行程／行程／Regular journey」，查詢結果使用「路線／路线／Route」。
- 所有圖示按鈕保留清楚的 content description；交換及底部導航觸控目標不得小於 `48dp`。
- TalkBack 焦點依畫面順序遍歷起點、目前位置、終點、交換、候選、查詢及結果操作；靜態預覽不得暴露無效操作。
- 深淺色保持相同版面、圓角、間距、展開方式及選中層級，只切換 semantic colors。
- 不以縮小字體、固定單行或裁切核心文字處理翻譯長度。

## 8. 驗證計劃

### 自動化驗證

- 驗證三個 Tab 在點擊、目的地切換和 Activity 重建後保持正確選中狀態。
- 驗證起點與終點候選清單位於對應欄位下方，同時只展開一個，並保持既有 debounce、數量限制及 IME 高度策略。
- 驗證交換涵蓋已選 Place、未完成文字、候選關閉及 Google attribution 歸屬。
- 驗證 attribution 在重建後恢復，並在文字修改或選擇 Citybus 候選後移除。
- 驗證搜尋與常用頁排序按鈕使用同一樣式，升降序切換及實際結果順序不變。
- 驗證首次空狀態不存在次要搜尋按鈕，「新增常用行程」仍開啟既有新增流程，底部搜尋目的地仍可使用。
- 更新受影響的 XML／UI contract 測試，並運行 `./gradlew build`。

### 人工及模擬器驗證

- 繁體、簡體、英文各驗證淺色及深色。
- 在 `360dp` 寬度模擬器驗證一般字體，以及 font scale `1.0／1.3／2.0`。
- 逐一檢查三個導航選中狀態、起點候選、終點候選、載入、無結果、失敗、交換及 attribution。
- 檢查長英文的結果摘要、「Save as regular journey」和排序項不裁切、不重疊。
- 檢查底部導航、輸入器、候選清單、結果操作和空狀態在切換時沒有不合理位移。
- 若沒有可用設備，交付時明確記錄未完成的手動視覺驗證。

## 驗收標準

1. 任一頂層頁面都能透過持續選中樣式辨認目前 Tab，且切換無布局跳動。
2. 起終點形成清楚的連體輸入關係，交換按鈕位於右側，候選及錯誤直接歸屬對應欄位。
3. Google attribution 在交換與重建後仍跟隨正確地點。
4. 搜尋與常用頁排序控件在所有狀態下視覺一致，排序行為沒有回歸。
5. 首次常用頁只提供「新增常用行程」主操作，並可透過底部搜尋 Tab 完成一次性查詢。
6. 三語、深淺色、窄屏和大字體下核心文字完整可讀，控件不重疊且觸控目標合格。
7. 完整構建通過，現有查詢、儲存、刷新、路線詳情及監控資料流未被改變。
