# 三模組導航與 Google 地圖整合設計

日期：2026-07-16
狀態：已確認

## 背景

BusIsComing 目前把常用路線、臨時查詢、查詢結果和設定入口集中在主頁。隨著功能增加，主頁同時承擔高頻通勤、一次性探索和低頻設定，資訊層級逐漸混雜。專案亦準備引入 Google Maps SDK for Android，以地圖方式展示站點和路線詳情。

本設計將 App 整理為「常用」「搜尋」「設定」三個頂層功能模組，並把地圖定位為 Citybus 路線結果的展示層。這裡的「功能模組」是 UI 與責任邊界，不是三個獨立 Gradle module；首版仍保留單一 `app` module，避免為畫面導航引入不必要的建置複雜度。

## 產品判斷

三模組調整合理，但成立的前提是「搜尋」必須成為完整的一次性路線探索流程，而不是只把臨時查詢改名。「常用」仍是預設首頁和最快通勤路徑；「搜尋」處理非日常起終點與地圖探索；「設定」雖然使用頻率較低，但可統一承載通知、定位、支援與關於，並清理首頁右上角入口。

採用漸進式地圖增強方案：搜尋初始頁以表單為主，查詢後以路線列表為主、地圖為可展開輔助；路線詳情沿用底部彈層並加入可展開地圖。此方案保留現有票價、耗時、步行距離及 ETA 的比較效率，同時讓地圖提供站點位置與路線空間關係。

## 目標

- 建立「常用」「搜尋」「設定」三個穩定的頂層入口。
- 把臨時查詢完整移至「搜尋」，並保留存為常用路線的轉換路徑。
- 在搜尋結果及路線詳情中展示站點、換乘與路線示意。
- 保留 Citybus 作為地點、候選路線、站序、ETA 和換乘資料的唯一業務來源。
- 地圖不可用時，既有路線查詢、ETA、站點時間線與通知監控仍可正常使用。
- 維持 XML、AppCompat、Material Components 和現有輕量 Repository 分層。

## 非目標

- 不拆分新的 Gradle feature module。
- 不使用 Jetpack Compose 重寫畫面。
- 不引入 Google Places 作為地點搜尋來源。
- 不使用 Google Routes 計算或取代 Citybus 候選路線。
- 不支援長按地圖選擇起終點。
- 不宣稱站序連線是貼合道路的精確巴士軌跡。
- 不顯示巴士即時車輛位置。
- 不在首版加入衛星圖、傾斜、旋轉或自訂地圖類型。

## 資訊架構

### 常用

「常用」是預設首頁，保留以下既有能力：

- 常用路線快捷選擇、全部路線與路線管理。
- 查詢結果、排序、下拉刷新、ETA、路線詳情和通知監控。
- 乘車碼入口。

原臨時查詢入口、臨時結果提示列、編輯臨時起終點和保存臨時路線操作移出此頁。原右上角設定按鈕亦移除。

### 搜尋

「搜尋」承接並升級原臨時查詢：

- 選擇起點和終點、使用目前位置及交換起終點。
- 查詢 Citybus 路線並展示既有結果卡資訊。
- 顯示選中路線的地圖、站點及換乘關係。
- 編輯目前查詢並將起終點配置存為常用。
- 開啟 ETA、路線詳情及適用的通知監控操作。

結果卡的資訊格式與「常用」一致，不為地圖另建一套簡化結果卡。

### 設定

「設定」承接目前設定頁、支援與關於。作為頂層頁面時不顯示返回箭頭；支援、關於及其他次級內容仍使用標準返回導航。設定頁不新增與本次需求無關的儀表板或裝飾內容。

### 導航規則

- 三個頂層頁面固定顯示底部導航，文案使用「常用」「搜尋」「設定」。
- 「常用」是冷啟動預設頁。
- 切換模組時保留各自的查詢結果、滾動位置、選中路線與地圖展開狀態。
- 路線管理、路線編輯、支援與關於等次級頁面不顯示底部導航，並保留返回行為。
- 路線詳情和 ETA 仍以 modal bottom sheet 呈現，不建立新的頂層頁面。

## UI 架構

`MainActivity` 調整為三個頂層 destination 的宿主，使用 `BottomNavigationView` 與 Fragment 容器。畫面責任拆分為：

- 常用路線 Fragment：承接目前主頁常用路線與查詢結果流程。
- 路線搜尋 Fragment：承接起終點表單、一次性查詢、地圖及保存為常用。
- 設定 Fragment：承接目前 `SettingsActivity` 的頂層設定內容。

常用與搜尋各自持有獨立的 UI state holder，避免切換頁籤後互相覆蓋查詢。兩者共用路線查詢協調、結果卡 Adapter、ETA、詳情彈層和監控入口。`MainActivity` 只負責頂層導航與 destination 恢復，不直接承擔 Citybus 查詢、地圖渲染或設定業務。

新增的地圖責任保持獨立：

- 地圖展示模型轉換器：把領域模型轉換為標記、分段、連線及相機範圍。
- Google 地圖渲染器：只負責把展示模型套用至 Google Map，不取得 Citybus 資料。
- 地圖 UI 狀態：記錄選中路線、選中站點、載入／錯誤與展開狀態，不保存 Google Map 實例。

## 搜尋流程

### 輸入狀態

首次進入且沒有既有查詢時，不顯示空地圖。頁面以起終點表單為主：

- 起點和終點必須沿用 Citybus 候選地點選擇。
- 起點可使用目前位置，名稱繼續由現有 Google 反向地理編碼能力解析。
- 交換起終點使用圖示按鈕。
- 主操作文案為「查詢路線」。
- 首版不新增近期搜尋、收藏地點或地圖選點。

### 載入狀態

提交後保留起終點摘要並顯示查詢進度。修改起終點時取消或忽略舊回應，防止過期結果覆蓋新查詢。Citybus 基礎結果返回後立即顯示列表，ETA、站點預覽及地圖詳情按既有增量方式補齊，不以地圖阻塞首屏結果。

### 結果狀態

完整表單收合為「起點 → 終點」摘要列，提供編輯和「存為常用」。下方先顯示約頁面四分之一至三分之一高度的小型地圖，再顯示可充分捲動的路線列表。

第一筆路線預設為選中路線。點擊其他路線卡時先更新選中狀態，再沿用既有行為開啟路線詳情彈層；關閉彈層後保留該路線的地圖高亮。地圖展開後約佔可用內容高度的一半，列表仍保留操作空間，底部導航不消失。

保存的是目前起終點配置，不是某一班巴士路線。保存成功後不強制跳轉「常用」，避免中斷目前比較；使用者下次切換「常用」即可看到新配置。

## 地圖展示

### 小型地圖

- 作為頁面全寬功能區域，不放入裝飾性卡片。
- 預覽狀態允許點擊站點與展開，但停用平移、縮放、旋轉及傾斜，避免攔截列表垂直捲動。
- 提供展開圖示及無障礙描述。
- 預設相機範圍涵蓋選中路線的起點、重要站點和終點。

### 展開地圖

- 啟用平移和縮放，繼續停用旋轉及傾斜。
- 提供「收合」和「重新顯示完整路線」圖示按鈕。
- 不提供衛星圖、地圖類型選單或獨立全屏頁。
- 地圖與路線列表保持同頁，收合後恢復原列表高度與滾動位置。

### 標記與線條

- 巴士路段使用品牌綠色實線。
- 不同換乘段可使用藍色輔助線及明確換乘標記。
- 起點至上車站、下車站至目的地使用灰色虛線。
- 普通途經站使用低強度小圓點；上車、換乘及下車站使用較大標記和角色文字。
- 角色不能只以顏色表達，必須同時使用形狀、圖示或文字。
- 有完整有序站點座標時才繪製站序連線；資料不完整時只顯示可靠標記，不補畫可能誤導的連線。

地圖使用低干擾的淺色樣式，弱化與通勤無關的 POI，但保留道路、區域名稱及 Google 必要標誌。Google 標誌和 attribution 不得被控制項、彈層內容或 WindowInsets 遮擋。

## 路線詳情彈層

沿用現有 `RouteDetailBottomSheet`，不改成獨立全屏頁：

- 標題下方加入地圖，一般狀態約佔彈層三分之一。
- 地圖展開後約佔彈層一半，底部仍顯示目前選中站點的時間線上下文。
- 點擊時間線站點會定位並高亮地圖標記。
- 點擊地圖標記會同步高亮時間線中的對應站點。
- 彈層關閉後，搜尋頁保留目前選中路線與地圖狀態。
- 地圖不是唯一資訊來源；所有站點與換乘資訊仍完整存在於可捲動時間線。

## 資料來源與載入策略

資料流如下：

```text
起終點 Place
    ↓
CitybusBusRouteRepository
    ↓
BusRouteOption 列表
    ↓ 選中一筆
CitybusRouteDetailRepository
    ↓
RouteDetail / RouteDetailLeg / RouteDetailStop
    ↓
地圖展示模型
    ├─ 搜尋頁地圖
    └─ 路線詳情彈層地圖
```

- Citybus 負責地點、候選路線、ETA、站序及換乘資料。
- Google Maps SDK 只負責底圖、標記、線條及相機操作。
- 查詢成功後只載入目前選中路線的詳情，不同時抓取所有候選路線。
- 切換選中路線時按需載入詳情，並沿用既有一天路線詳情快取。
- 搜尋頁和詳情彈層共用同一份地圖展示模型，避免標記角色或分段不一致。
- 現有 Google 反向地理編碼只負責目前位置命名，不與地圖路線計算耦合。
- Google API key 延續外部設定注入方式，不提交到倉庫；Maps SDK 的 key 限制和發布設定在實作與發布驗證中單獨核對。

## 錯誤與降級

- Citybus 查詢失敗：保留起終點，顯示錯誤與重試，不建立空地圖。
- 路線詳情載入中：地圖區顯示輕量載入狀態，結果列表仍可操作。
- 路線詳情失敗：保留路線卡與已知站點摘要，地圖區提供重試，不影響 ETA 與監控。
- Google 地圖、Google Play Services 或網路不可用：地圖區顯示「地圖暫時無法載入」與重試；路線列表、ETA、站點時間線和通知監控繼續工作。
- 定位權限拒絕：目前位置入口按既有規則降級，使用者仍可手動選擇 Citybus 地點，不反覆要求權限。
- 座標不完整：只展示可靠標記，不繪製不完整或推測路線。

## 狀態與生命週期

- 三個頂層 Fragment 保留各自的查詢與滾動狀態。
- 旋轉或 Activity 重建後恢復選中頁籤、搜尋條件、結果、選中路線和地圖展開狀態。
- Google Map、marker 和 polyline 等 SDK 物件不寫入 `Bundle`、資料庫或持久化狀態；重建後由地圖展示模型重新渲染。
- 地圖延遲到存在可展示結果時才初始化，並正確轉發宿主生命週期，避免首頁冷啟動為未使用的地圖支付成本。
- Fragment 或彈層關閉後忽略遲到的詳情和地圖回應。

## 無障礙與穩定尺寸

- 地圖控制圖示提供繁體中文 content description，觸控區域至少 48dp。
- 站點角色同時使用顏色、形狀或文字，不只依賴顏色。
- TalkBack 使用者可從時間線取得與地圖等價的站點與換乘資訊。
- 地圖預覽、底部導航、排序控制和路線卡使用穩定高度，載入與錯誤狀態不得推動整頁跳動。
- 小螢幕、大字體和長站名下，標題與操作不得互相遮擋；站名必要時尾端省略，但詳情時間線保留完整可讀內容。

## 驗證

### 單元測試

- `RouteDetail` 至地圖展示模型的轉換。
- 上車、換乘、普通途經及下車站角色映射。
- 多段路線、步行虛線與站序連線。
- 缺失或無效座標時的標記與連線降級。
- 選中路線、選中站點和相機範圍計算。
- 過期查詢及詳情結果被忽略。

### UI 與 instrumentation 測試

- 三個底部模組切換、預設頁及狀態保留。
- 搜尋輸入、載入、結果、編輯與存為常用。
- 小型地圖展開／收合及列表滾動位置恢復。
- 路線卡選中、詳情彈層、站點雙向聯動與返回。
- 地圖不可用、詳情失敗、無網路及定位權限拒絕時的降級。
- 設定頁作為頂層頁時沒有返回箭頭，首頁沒有舊設定入口。

### 手動驗證

- 在具備 Google Maps key 的模擬器或真機確認地圖非空白、相機範圍正確、標記和連線可見。
- 驗證窄屏、大字體、旋轉重建與不同 Android API level。
- 驗證小型地圖不攔截列表捲動，展開地圖的平移與縮放正常。
- 驗證 Google 標誌與 attribution 未被底部彈層、控制按鈕或系統 Insets 遮擋。
- 發布前核對 API key 限制、計費、隱私政策與 Play Data Safety 聲明。
- 最終運行 `./gradlew build`；涉及地圖 UI 的 instrumentation 測試在有可用設備與 key 的環境執行。

## 實作順序建議

### 交付拆分

本設計應拆成兩個可獨立驗證、依序交付的實作階段：

- 階段一「三模組導航與搜尋遷移」：建立底部導航和三個頂層頁面，把臨時查詢遷移至「搜尋」，完成狀態隔離與既有功能回歸；此階段不接入地圖。
- 階段二「Google 地圖路線展示」：在階段一的搜尋頁和既有詳情彈層接入地圖展示模型、Google Maps SDK、站點聯動及錯誤降級。

階段二依賴階段一提供穩定的搜尋頁與結果狀態。每個階段均應有獨立的實作計劃、測試範圍和可提交結果，避免在同一次變更中同時處理主頁拆分、查詢遷移、地圖生命週期及第三方 API 設定。

### 建議次序

1. 建立三個頂層 destination 與底部導航，完成現有功能遷移及狀態隔離。
2. 把原臨時查詢遷移至「搜尋」，先在沒有地圖的情況下完成端到端回歸。
3. 建立純 Kotlin 地圖展示模型和轉換測試。
4. 接入 Google Maps SDK，完成搜尋頁小型／展開地圖。
5. 在路線詳情彈層復用地圖展示模型並加入站點雙向聯動。
6. 補齊錯誤降級、生命週期、無障礙、instrumentation 與發布檢查。

此順序讓導航重構、功能遷移和第三方地圖接入可以分段驗證，降低同時改動主頁、查詢流程及地圖生命週期的風險。
