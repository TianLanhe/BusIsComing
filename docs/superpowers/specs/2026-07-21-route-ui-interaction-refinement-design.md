# 路線查詢介面與互動細節優化設計

日期：2026-07-21

## 背景

目前 App 已完成「常用／搜尋／設定」三個頂層模組、搜尋頁及 Google Maps 相關能力，但常用頁的結果可視空間、路線卡片的英文站名、底部導覽選中狀態、搜尋頁輸入與保存入口，以及乘車碼的入口層級仍有改善空間。

本次設計聚焦於既有功能的視覺層級、滾動行為和互動狀態，不改變 Citybus 查詢語義、已保存行程資料格式或路線詳情彈層的主要動線。

## 目標

- 讓常用頁優先展示常用行程與路線結果，減少非結果內容佔用的固定高度。
- 讓排序與結果摘要在長列表中持續可用，但不固定常用行程和查詢控制。
- 讓三種語言的上落車站名保持單行、卡片高度穩定，並盡量保留可辨識內容。
- 讓底部導覽的選中狀態在動畫結束後仍然清晰，且不再擠壓圖示或標籤。
- 簡化搜尋頁，讓保存常用行程、排序、輸入和自動定位各自落在正確層級。
- 讓乘車碼在需要時快速可達，但完全不佔用常用頁的內容空間。
- 所有變更同時適用於繁體中文、簡體中文、英文，以及淺色與深色模式。

## 非目標

- 不改變 Citybus 搜尋、路線查詢、ETA 或 Google Geocoding 的服務端協議。
- 不重新設計路線詳情底部彈層、ETA 彈層或新增／編輯行程頁。
- 不改變 SQLite schema、既有行程資料或匯入匯出格式。
- 不在常用頁加入新的頁面大標題、懸浮按鈕或第二層底部工具列。
- 不以縮小核心文字、跑馬燈或整列橫向捲動處理長站名。

## 1. 常用頁結構

### 1.1 標題與操作

- 「常用行程」「全部」「管理」恢復在同一水平列，視覺上沿同一基線排列。
- 「常用行程」佔用剩餘寬度；「全部」與「管理」維持文字操作和至少 48dp 觸控範圍。
- 不新增「常用」頁面大標題。
- 常用頁不再展示任何乘車碼按鈕、懸浮入口或固定工具列。
- 無障礙大字體下可增加該列高度，但操作不可被裁切、重疊或移出觸控範圍。

### 1.2 密度

- 頁面水平邊距由目前偏寬的配置收斂至 16dp。
- 標題列、常用行程快捷卡、查詢按鈕、排序區和結果摘要之間使用 8 至 12dp 的節奏，移除可合併的 14 至 20dp 空白。
- 視覺高度可以收緊，但按鈕和文字操作的有效觸控高度不得低於 48dp。
- 排序區下方應盡快出現第一張路線卡，避免非結果區在一般手機首屏佔據約一半空間。

### 1.3 捲動與吸頂

常用頁形成一個連續的垂直捲動體系：

1. 常用行程標題和操作。
2. 常用行程快捷卡。
3. 查詢按鈕。
4. 排序項。
5. 路線數量和更新時間摘要。
6. 路線結果列表。

向下捲動時，常用行程、快捷卡和查詢按鈕隨內容移出畫面；只有「排序項＋結果摘要」組合吸頂。吸頂區不得遮住狀態列、系統 Insets 或第一張結果卡。

建議沿用 Android 巢狀捲動能力，以 `CoordinatorLayout/AppBarLayout` 或等價的單一巢狀捲動結構實現，不把標題或查詢控制偽裝成 RecyclerView 資料項。

## 2. 路線結果卡片

### 2.1 保持現有邊界

- 站名仍位於路線名稱下方的左側文字列 `busRouteTextColumn`。
- 站名區域的縱向位置、左邊界、右邊界、總寬度和 14sp 字號保持不變。
- 右側 ETA、下一班時間和通知鈴鐺的寬度、位置與互動保持不變。
- 站名不得延伸成橫跨整張卡片的一整行。

### 2.2 三語自適應單行方案

目前 `RouteDetailDisplayFormatter.stationDisplayName` 已取 Citybus 原始站名逗號前的主要名稱。保留這個安全規則，不再自行縮寫、翻譯或刪除主要名稱中的詞語。

原本的單一 `TextView` 改為同一既有寬度內的三段式結構：

```text
[上車站單行文字] [固定箭頭] [下車站單行文字]
```

- 繁體中文、簡體中文和英文使用同一套分配規則。
- 兩端都短時按內容寬度展示，不刻意製造空白。
- 一端短、一端長時，短端優先完整顯示，長端取得剩餘空間。
- 兩端都長時，各自至少保留約 32% 的文字可用寬度，單端最多使用約 68%。
- 箭頭寬度固定且始終可見。
- 超過最終可用寬度時才使用尾部省略。
- 不使用跑馬燈、手勢橫向捲動或自動縮小字體。
- 完整站名繼續在路線詳情彈層中展示，卡片的無障礙描述亦包含完整起終點。

同一字體比例下，站名固定為一行，使卡片行數與高度可預期。大字體模式可以按系統排版需求增加卡片整體高度，但站名本身仍不換行。

## 3. 底部導覽

- 三個 Tab 維持固定等寬槽位，選中狀態不得改變槽位尺寸或推動相鄰項目。
- 所有圖示均使用 24dp；選中後不再放大至 28dp。
- 選中圖示背後顯示類似 Google Play 的 64×32dp 膠囊指示背景，只包圍圖示，不延伸至標籤。
- 未選中標籤使用 12sp Regular；選中標籤使用 13sp Bold。
- 為 13sp 選中標籤預留穩定佈局空間，切換時不產生上下跳動或與指示背景重疊。
- 點擊後使用約 150ms 的顏色與透明度過渡；動畫結束後，膠囊背景、強調色和粗體標籤持續保留。
- 大字體模式可增加導覽列高度，不得壓縮或裁切標籤。
- 深色模式保持相同尺寸，以對應的表面色、選中容器色和前景語義色呈現。

## 4. 搜尋頁

### 4.1 頂部與輸入器

- 刪除頁面頂部 24sp 的「搜尋／搜索」大標題。
- 保留「輸入起點與終點，探索可用巴士路線」功能說明，並將輸入器與頁面頂部的間距收緊。
- 起點和終點輸入文字明確使用 16dp 左內邊距；右側保留 52dp 工具空間，避免文字、光標和定位圖示重疊。
- 輸入文字維持 16sp；浮動標籤與輔助文案沿用 Material TextInput 的語義層級。
- 焦點外框和約 2dp 光標使用高對比主題強調色。深色模式提供相同可見度，不依賴系統預設光標色。
- 輔助文案只在空值獲得焦點、正在輸入、無候選或錯誤狀態下歸屬於對應輸入框；有效地點選定後隱藏一般操作提示。
- 交換按鈕繼續位於兩個輸入框右側並垂直置中，維持 48dp 觸控範圍。

### 4.2 首次自動定位

首次在一個 `MainActivity` 實例中切換到搜尋頁、且沒有恢復或已有起點時，搜尋頁自動執行與「新增行程」一致的流程：

```text
取得手機位置
→ Google Reverse Geocoding
→ 以地址名稱＋原始經緯度建立選中起點
→ 顯示必要的 Google Maps 地址歸因
```

行為規則：

- 定位和 Geocoding 全程在背景執行，不顯示阻塞彈層。
- 起點和終點輸入器始終可用；自動定位不得鎖定鍵盤、候選列表或交換以外的正常輸入。
- 定位中僅把起點尾部定位圖示替換為小型進度指示。
- 使用者可以在定位期間直接輸入或選擇終點，且不會中斷起點自動定位。
- 使用者開始修改或選擇起點時，立即遞增請求 generation、取消等待狀態並使舊定位／Geocoding 回調作廢。
- 使用者交換起終點時同樣使自動定位回調作廢。
- 搜尋按鈕只依「起點和終點是否都是有效選中地點」決定可用狀態，不依定位任務是否仍在執行。
- 成功後填入具體地址名稱和經緯度，不引入「我的位置」特殊占位值。
- 定位、權限、系統定位開關、逾時或 Geocoding 任一步失敗時，不保留半完成的座標地點；起點保持可編輯狀態，並以輔助文案提示使用者手動選擇起點或點擊定位圖示重試。
- 自動請求失敗時不強制跳轉系統設定；手動點擊定位圖示時沿用新增行程現有的權限與系統設定恢復流程。
- 畫面重建時如已恢復起點、使用者文字或已提交查詢，不再次自動覆蓋。

### 4.3 保存常用行程

- 刪除整個 `searchResultSummaryContainer` 所承載的臨時結果區，包括重複的「起點 → 終點」摘要和「編輯」按鈕。
- 「存為常用行程」屬於當前起終點組合，不屬於某一條路線卡。
- 保存按鈕放在兩個輸入框下方、左側 `searchPlaceColumn` 內；不擴展至右側交換按鈕槽位。
- 只有當目前起終點成功取得非空路線結果，且結果仍對應當前選中地點時才顯示保存按鈕。
- 編輯文字、重新選擇地點、交換起終點或發起新查詢時立即隱藏；新查詢成功後再顯示。
- 點擊後沿用既有 `TemporaryRouteSaveDialog`、行程命名、重複檢查與保存完成提示。
- 自動定位成功時已取得具體地址；保存階段不再額外呼叫 Geocoding。

### 4.4 搜尋結果

搜尋結果移除臨時摘要後，順序統一為：

1. 與常用頁相同的橫向排序按鈕。
2. 同一水平列的「路線數量」與「更新時間」。
3. 路線結果卡片。

搜尋頁和常用頁共用 `RouteResultSortButton` 的尺寸、描邊、選中背景、文字與箭頭格式，不各自維護視覺變體。

## 5. 乘車碼入口

乘車碼完全移出常用頁，採用已確認的「系統快捷方式＋候車通知」三層入口。

### 5.1 App 圖示快捷動作

- 發佈靜態 App Shortcut「乘車碼」，讓使用者長按 BusIsComing 圖示即可開啟。
- 快捷動作直接觸發既有 `TransitCodePaymentLauncher` 的 AlipayHK／Alipay 回退鏈，不先導向常用頁。

### 5.2 桌面固定快捷方式

- 設定頁新增「乘車碼快捷方式」列，說明其用途為「從桌面一按開啟」。
- 使用 Android pinned shortcut API 由使用者確認添加。
- 已存在快捷方式時顯示已添加狀態或允許重新添加，不在常用頁持續宣傳。

### 5.3 候車通知

- 現有候車監控通知由「重新整理／停止」兩個操作擴充為「重新整理／乘車碼／停止」。
- 乘車碼只在候車監控通知存在時出現，屬於接近上車時機的情境化入口。
- 點擊後啟動同一乘車碼回退鏈，不停止監控服務。
- 無法開啟 AlipayHK 或 Alipay 時沿用既有失敗提示與安全日誌，不讓通知 action 靜默失敗。

建議把 Shortcut 與通知 action 導向同一個明確的 App intent action，再由單一入口調用 `TransitCodePaymentLaunchAction`，避免三個入口各自複製 provider 回退邏輯。

## 6. 狀態與併發

- 搜尋頁自動定位、手動定位、使用者輸入和 Fragment 顯示／隱藏共用明確 generation；任何較舊回調不得更新畫面。
- 離開搜尋頁時取消畫面等待狀態並使當前查詢、定位或 Geocoding UI 回調作廢；已選中地點和使用者文字按現有保存狀態規則保留。
- App 語言切換後，舊語言的 Geocoding 回調不得覆蓋新語言畫面；新請求使用 `LanguageSnapshot` 的 Google 語言與地區映射。
- 保存按鈕的可見性應由「結果 query id／generation 與當前起終點相符」推導，而不是只依列表是否非空。
- 路線卡片的非同步 ETA 與站名補齊不得改變卡片的站名行數或導致列表跳動。

## 7. 錯誤處理

- 自動定位失敗：起點下方輔助文案，不彈 Toast，不跳設定。
- 手動定位失敗：沿用現有 Toast；系統定位關閉時可引導至設定並在返回後重試。
- Google Geocoding 失敗：視為此次定位流程失敗，不建立只有座標、沒有可見名稱的搜尋起點。
- 搜尋失敗：隱藏保存按鈕；刷新失敗且已有結果時保留既有結果和排序。
- 空結果：顯示空結果狀態，不顯示保存按鈕。
- Shortcut／通知乘車碼失敗：顯示既有三語錯誤提示，不影響候車監控。

## 8. 多語言、深色與無障礙

- 所有新增或修改文案同時提供香港繁體、獨立簡體與自然英文版本，不在 Kotlin 或 XML 中硬編碼 App 可見文字。
- 三語站名使用相同自適應寬度算法，但保留第三方原文，不機器翻譯或自行縮寫。
- 淺色與深色使用同一結構；焦點框、光標、排序選中態、導覽膠囊、保存按鈕及定位錯誤文案均使用語義色資源。
- 觸控目標至少 48dp，IconButton 提供本地化 `contentDescription`。
- 在 360dp、font scale 1.0／1.3／2.0 下，核心文字不得與圖示重疊或被無提示裁切；路線卡片站名是明確允許尾部省略的例外，完整內容由詳情與無障礙描述提供。

## 9. 驗證方案

### 自動化測試

- 自適應站名寬度策略：兩端短、一短一長、兩端長、三種語言、極端長單詞。
- 路線卡片綁定：站名固定一行、箭頭固定、完整無障礙描述保留。
- 搜尋頁狀態：標題不存在；保存按鈕僅在結果與輸入 generation 相符時顯示。
- 自動定位：非阻塞輸入；修改起點和交換使舊回調失效；輸入終點不取消起點定位；失敗顯示輔助文案。
- Geocoding：成功保存地址與原始座標；失敗不建立半完成 `Place`；語言切換作廢舊回調。
- 底部導覽：選中樣式在動畫後持續；圖示尺寸固定；標籤文字樣式正確。
- 乘車碼：靜態／固定 Shortcut intent、通知第三個 action、provider 回退及失敗處理。

### 裝置／模擬器驗證

- 繁中、簡中、英文 × 淺色、深色。
- 360dp 和一般寬度裝置，font scale 1.0／1.3／2.0。
- 常用頁長列表捲動：只有排序與摘要吸頂。
- Google Play 風格底部導覽：選中背景不碰觸標籤。
- 搜尋頁首次進入：定位中立即輸入終點；定位成功；拒絕權限；關閉定位；Geocoding 失敗；手動重試。
- 搜尋、交換、修改起點後確認舊回調不覆蓋。
- 添加桌面 Shortcut、長按 App 圖示及候車通知開啟乘車碼。

### 構建

最終實現完成後執行：

```bash
./gradlew build
```

## 10. 相容性與遷移

- 不需要資料庫或已保存行程遷移。
- 既有 `RouteConfig`、Citybus 查詢和通知監控 session 保持兼容。
- 被移除的搜尋結果摘要 view 和常用頁乘車碼 view 不保留隱藏死代碼；相關測試應同步改為新入口與新狀態契約。
