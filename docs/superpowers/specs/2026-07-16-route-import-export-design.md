# 常用路線匯入與匯出設計

日期：2026-07-16

## 背景

BusIsComing 目前將常用路線保存在本機 SQLite。每條路線包含路線名稱、起點及終點的地點名稱與經緯度，並另行保存使用次數和最近使用時間。App 已有獨立 `設定` 頁，但尚未提供在用戶之間傳遞常用路線的能力。

本功能主要解決「將自己的常用路線檔案交給另一位 BusIsComing 用戶」的情境。它不是完整 App 備份，也不傳遞個人使用統計、查詢結果、定位快取或其他裝置狀態。

## 目標

- 在 `設定` 頁新增單一入口，讓用戶進入專用的路線匯入與匯出頁。
- 將目前全部常用路線匯出為可由另一個 BusIsComing 安裝匯入的 `.bicroutes` 檔案。
- 匯入前完整校驗並預覽路線，讓用戶選擇合併或取代。
- 以原子資料庫交易執行匯入，任何失敗均不留下部分結果。
- 不新增 Android 儲存權限，使用系統文件選擇器讀寫用戶指定的位置。
- 保持格式可版本化、核心邏輯可 JVM 單元測試。

## 非目標

- 不提供選擇單條或多條路線匯出，本期只支援全部匯出。
- 不直接打開系統分享面板；用戶先將檔案保存到指定位置，再自行傳遞。
- 不匯出或還原使用次數、最近使用時間、SQLite id、建立時間與更新時間。
- 不提供密碼、加密、簽名、雲端同步、帳號同步或自動備份。
- 不直接匯出 SQLite 資料庫。
- 不導入 Citybus 查詢結果、ETA、通知監控 session 或目前定位。

## 資訊架構與頁面

### 設定頁入口

在既有 `偏好` 與 `支援` 分組之間新增 `路線資料` 分組，分組內只有一個 item：`匯入與匯出常用路線`。點擊後打開標題為 `路線匯入與匯出` 的專用二級頁。

專用頁沿用既有設定頁的淡綠背景、白色實體卡片、8dp 左右圓角、深青綠文字與返回入口。頁面包含：

1. `匯入路線` 卡片：說明可從 `.bicroutes` 檔案合併或取代，操作為 `選擇檔案並預覽`。
2. `匯出全部路線` 卡片：顯示目前可匯出的路線數，操作為 `全部匯出`。

當目前沒有常用路線時，匯出按鈕保持可見但禁用，並顯示沒有可匯出路線的說明。匯入入口仍可使用。

### 匯出流程

1. 用戶點擊 `全部匯出`。
2. 每次均顯示隱私確認：`檔案包含全部常用路線及地點資料，請只分享給信任的人。`
3. 用戶確認後，透過 Android Storage Access Framework 的 `CreateDocument` 讓用戶選擇保存位置；建議檔名為 `BusIsComing-routes-YYYYMMDD-HHmm.bicroutes`。
4. App 讀取當下全部常用路線、建立完整檔案內容並寫入所選 URI。
5. 成功後停留在本頁，顯示匯出路線數量；取消文件選擇器則靜默返回。

匯出使用 MIME `application/octet-stream`，確保保留自訂 `.bicroutes` 副檔名。匯入的 `OpenDocument` 接受通用 MIME，因不同文件供應器可能無法辨識自訂副檔名；當供應器能提供檔名時必須以 `.bicroutes` 結尾，無法提供檔名時則以文件內的格式標記及完整校驗為準。App 不要求永久 URI 權限，也不新增外部儲存權限。

### 匯入流程

1. 用戶點擊 `選擇檔案並預覽`，透過 Storage Access Framework 選擇檔案。
2. App 以最多 `2 MiB + 1 byte` 的有界讀取方式取得內容，避免文件供應器未提供可靠大小時無限制讀取。
3. App 驗證副檔名、大小、JSON 結構、格式標記、版本、路線數及每個欄位。
4. 全部通過後才建立只讀預覽，顯示檔名、有效路線數、重複數及完整路線名稱清單。
5. 預覽同時顯示兩種模式的影響：
   - `合併匯入`：將新增多少條，將跳過多少條重複路線。
   - `取代現有路線`：將刪除多少條現有路線，並匯入多少條檔案路線。
6. `合併匯入` 可直接執行；`取代現有路線` 必須再顯示警告對話框：`現有 X 條路線將永久刪除，並改為匯入 Y 條路線。此操作無法復原。`
7. 寫入成功後回到專用頁的操作首頁，持續顯示結果摘要。用戶返回主頁時，既有 `MainActivity.onResume()` 重新載入路線。

返回預覽上一頁、取消文件選擇器或取消取代確認均不修改任何資料，也不顯示錯誤。

## 檔案協議

### 外層結構

`.bicroutes` 是未加密的 UTF-8 JSON。版本 1 範例：

```json
{
  "format": "com.golink.busiscoming.routes",
  "version": 1,
  "exportedAt": "2026-07-16T10:30:00Z",
  "routes": [
    {
      "name": "屋企返公司",
      "origin": {
        "name": "漁灣村漁進樓",
        "latitude": 22.264,
        "longitude": 114.248
      },
      "destination": {
        "name": "會展站",
        "latitude": 22.2816,
        "longitude": 114.175
      }
    }
  ]
}
```

`format`、`version`、`exportedAt` 和 `routes` 均為必要欄位。版本 1 只接受已定義欄位；缺少必要欄位、出現未知欄位、格式標記不符或版本不是 `1` 均拒絕整份檔案。未來新增不相容欄位時必須提升版本，舊版 App 對未知版本顯示更新提示，不嘗試猜測解析。

### 路線欄位

每條路線只包含：

- `name`
- `origin.name`
- `origin.latitude`
- `origin.longitude`
- `destination.name`
- `destination.latitude`
- `destination.longitude`

檔案不得包含或匯入 SQLite id、使用次數、最近使用時間、建立時間或更新時間。匯入時由本機重新建立 id 與時間；新路線的使用次數為 `0`，最近使用時間為 `null`。

### 限制與校驗

- 檔案大小不得超過 2 MiB。
- `routes` 必須包含 1 至 500 條路線；0 條路線的檔案無效，不可用於清空資料。
- 路線名稱 trim 後不得為空。
- 起點及終點地點名稱不得為空。
- 緯度和經度必須是有限數字；緯度範圍為 `-90..90`，經度範圍為 `-180..180`。
- 起點與終點不得完全相同。
- 任一非法欄位均使整份檔案失敗，不進入預覽，也不寫入部分有效路線。

### 重複判定

路線名稱 trim 後相同、起點 `Place` 相同且終點 `Place` 相同時，才視為完全重複。相同名稱但不同起終點，或相同起終點但不同名稱，均是不同路線。

檔案內完全重複的項目只保留第一條，其餘計入跳過數量。合併時再與現有資料套用相同判定：

- 既有路線保持原 id、使用次數和最近使用時間。
- 不重複的檔案路線以新記錄插入，使用統計從 0 開始。
- 重複路線不更新、不覆蓋，也不重置既有統計。
- 若全部項目都重複，操作視為正常完成，顯示 `沒有新增路線，已跳過 X 條重複路線。`

取代模式會先在同一 transaction 中刪除現有路線，再插入檔案內去重後的路線；所有匯入路線的使用統計從 0 開始。

## 架構與組件

### `RouteTransferActivity`

負責專用頁、文件選擇器、隱私提示、匯入預覽、模式選擇、取代確認、載入狀態與結果摘要。Activity 不直接拼接 JSON，也不直接執行 SQL。

### `RouteTransferModels`

定義文件 DTO、預覽模型、`MERGE`／`REPLACE` 模式、匯入計劃、成功摘要及具體錯誤類型。UI 只依賴這些明確結果，不解析例外文字。

### `RouteTransferCodec`

純 Kotlin 組件，負責版本 1 編碼、解碼、結構校驗、欄位校驗及檔案內去重。它不依賴 Activity、ContentResolver 或 SQLite，可由 JVM 測試直接覆蓋。

### `RouteConfigRepository`

沿用 `getAll()` 作為匯出資料來源，新增明確的批量合併及取代能力。所有匯入寫入都使用單一 SQLite transaction：

- 合併在 transaction 內再次檢查重複，避免預覽至確認期間資料變化造成錯誤。
- 取代的刪除與插入必須在同一 transaction；任一步驟失敗即回滾。
- Repository 回傳實際新增、跳過及刪除數量，UI 不以預覽估計值假裝成功結果。

### 背景工作

文件讀取、解析、編碼、寫入和資料庫交易均不在主線程執行。處理期間禁用會重複啟動同一操作的按鈕並顯示輕量進度。Activity 銷毀後，背景結果不得更新舊頁面。

## 狀態恢復

旋轉或其他 configuration change 時，只保存待預覽文件 URI、檔名與目前頁面階段，重新讀取並校驗文件；不將最多 500 條路線序列化進 Bundle。若臨時 URI 權限已失效或進程恢復後無法讀取，頁面返回操作首頁並提示重新選擇檔案。資料庫已完成的匯入結果不依賴頁面狀態恢復。

## 錯誤處理

- 無法讀取或副檔名不符：提示無法讀取有效的 BusIsComing 路線檔案。
- 文件超過 2 MiB、路線超過 500 條或為空：顯示對應限制。
- JSON、格式或欄位非法：提示檔案內容損壞或不合法。
- 版本不支援：提示先更新 App，不進入預覽。
- Repository 寫入失敗：回滾 transaction，提示匯入失敗且現有路線未變。
- 匯出編碼失敗：不打開文件選擇器。
- 匯出寫入失敗：關閉 stream，盡力刪除不完整文件並顯示失敗提示。
- 用戶主動取消：靜默返回，不顯示錯誤。

匯出先在記憶體產生受 2 MiB 上限保護的完整 byte array，再一次性寫入所選 URI，降低留下部分文件的風險。

## 隱私與安全

- 檔案未加密，包含所有常用路線的地點名稱和精確座標。
- 每次匯出均顯示隱私警告，不提供「不再提示」。
- App 不自動上傳、不自動分享，也不保存用戶所選文件的永久存取權。
- 僅憑副檔名不足以信任檔案；匯入必須通過完整大小、格式、版本與欄位校驗。
- 對文件內容的錯誤提示不回顯完整路線資料或座標。

## 無障礙與版面

- 所有主要操作具備至少 48dp 觸控高度。
- 預覽清單可滾動，長路線名稱不與模式按鈕重疊。
- 大字體下卡片可增高，操作不得依賴固定 52dp 文字容器。
- TalkBack 應讀出檔名、路線數、合併／取代影響、危險操作和完成摘要。
- `取代現有路線` 使用危險色及明確文字，不只依靠顏色表達風險。

## 測試與驗收

### JVM 測試

- 版本 1 往返編碼與解碼。
- 匯出內容不包含 id、使用統計或本機時間戳。
- 大小、數量、空檔案、缺欄位、未知欄位、未知格式、未知版本、非法 JSON、非有限數字及越界座標。
- 路線名稱 trim、起終點相同及檔案內去重。
- 合併計劃的新增／跳過數量，以及取代影響數量。

### Repository instrumentation 測試

- 合併新增路線、跳過完全重複路線並保留既有統計。
- 取代刪除既有路線、重建匯入路線並將統計設為 0／null。
- transaction 中途失敗時合併及取代均完整回滾。
- 預覽後資料發生變化時，以交易內實際結果為準。

### UI 與 contract 測試

- `設定` 頁顯示 `路線資料` 分組與單一入口。
- 專用頁在 0 條及多條路線時的匯入／匯出狀態。
- 每次匯出的隱私提醒、CreateDocument、取消與成功摘要。
- OpenDocument、完整預覽、合併、取代二次確認、取消及完成摘要。
- 不合法檔案不顯示預覽且不改變資料。
- 旋轉恢復、大字體、長路線名稱及 TalkBack 語義。
- Manifest 不新增外部儲存權限。

最終實作驗證執行相關 JVM／instrumentation 測試、`./gradlew build` 及 OpenSpec strict validation。

## OpenSpec 影響

後續 proposal 應：

- 新增路線匯入／匯出能力規格，覆蓋文件協議、預覽、合併、取代、原子性、限制與錯誤處理。
- 修改 App 設定能力規格，加入 `路線資料` 分組、專用二級頁及返回行為。
- 修改路線配置管理／儲存能力規格，定義批量匯入後的重複判定與使用統計語義。
- 修正早期 `route-config-management` active spec 仍寫著「允許完全重複路線」，但目前程式及較新 `route-management-actions` 規格已禁止完全重複的矛盾。此修正只使規格符合目前實際行為，不額外改變手動新增或編輯流程。

## 已確認決策

- 主要情境是將路線檔案分享給另一位用戶。
- 設定頁採用新的 `路線資料` 分組及專用二級頁。
- 只支援全部匯出，不提供路線多選。
- 匯出使用系統保存位置選擇器，不直接打開分享面板。
- 使用自訂 `.bicroutes` 副檔名，內部為版本化 JSON。
- 匯入先顯示完整名稱預覽，再選擇合併或取代。
- 重複判定要求路線名稱、起點及終點全部相同。
- 任一非法路線使整份檔案失敗。
- 取代需要顯示刪除／匯入數量的二次確認。
- 使用統計不進入檔案。
- 空路線不可匯出，空檔案不可匯入。
- 每次匯出均顯示隱私提示。
- 匯入成功後留在專用頁並顯示摘要。
- 文件不加密。
- 文件上限為 2 MiB，路線上限為 500 條。
