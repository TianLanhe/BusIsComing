# 路線卡片圖示與全屏路線詳情頁設計

日期：2026-08-02
狀態：已確認

## 背景

目前路線結果卡片以文字標示耗時與步行距離，資訊層級偏平；路線詳情則以 Bottom Sheet 顯示少量站點資料，沒有把 Citybus P2P 詳情中可取得的起點步行、換乘步行、終點步行、預計上下車時間與分段票價組織成可直接依序執行的行動鏈。產品亦計劃在後續加入 Google 地圖，因此詳情需要先成為可承載地圖與長路線內容的獨立頁面。

## 目標

- 以已確認的鬧鐘與步行人物矢量圖示提升路線卡片的掃讀效率，但保持卡片步行距離及排序語義不變。
- 將路線詳情改為獨立全屏頁，完整呈現「起點 → 步行 → 巴士 → 換乘 → 巴士 → 步行 → 終點」。
- 清楚區分 Citybus 預計時刻與 DATA.GOV.HK 首程即時 ETA。
- 讓乘車、步行、同站換乘、上下車及途經站具有穩定且可存取的視覺語義。
- 為後續 Google 地圖模組保留插入位置，但本次不顯示空白地圖佔位。

## 非目標

- 不改變路線卡片由 `ppsearch_p3.php` 取得的步行距離或步行排序邏輯。
- 不在本次接入 Google Maps、步行導航或步行時間推算。
- 不為後續換乘段偽造即時 ETA。
- 不改動通知欄監控流程。

## 已確認的路線卡片圖示

- 耗時使用 18dp 細線小鬧鐘；圓形鐘面、雙鐘鈴與短指針均使用圓角線帽。
- 步行使用依使用者參考圖量測及平滑擬合的四塊獨立實心矢量輪廓；不得打包或縮放低解像度參考點陣圖。
- 兩個圖示使用次要文字語意色，並與數值保持緊湊的行內間距。
- TalkBack 應讀出完整的「耗時 N 分鐘」與「步行 N 米」，圖示本身不重複朗讀。

## 全屏頁資訊架構

頁面使用固定 App Bar 與單一可捲動內容區：

1. 返回按鈕與「路線詳情」標題。
2. 路線摘要：路線鏈、總耗時、預計到達時間、總票價、總途經站數及詳情完整步行距離。
3. 未來可選地圖模組；本次維持 `GONE`／不存在，不留下空白區域。
4. 行動時間線：起點步行、各乘車段、換乘、終點步行及目的地。

摘要範例：

```text
N8P → N969                        預計 01:21 到達
全程 49 分鐘
HK$51.2 · 共 14 站 · [步行人物] 403 米
```

「共 N 站」等於各乘車段途經站數之和，不重複計算上下車與換乘端點。詳情完整步行距離優先合計所有已取得的起點、換乘及終點步行段；若分段不完整，摘要回退使用卡片距離，但不得把回退值描述為已知的完整總步行距離。

## 時間線視覺語義

- 巴士乘車使用粗實線；相鄰乘車段按段序使用不同的無障礙顏色。
- 路線牌、乘車線與未來地圖折線使用同一分段顏色。顏色只在目前路線內區分分段，不聲稱是官方路線顏色。
- 起點、換乘及終點步行使用中性灰細虛線與已確認的步行人物圖示。
- 同站換乘顯示文字節點，不繪製虛假的步行距離。
- 起點、上車、下車、途經站與終點使用不同大小或形狀的節點；顏色不是唯一資訊通道。
- 紅色只保留給錯誤、停運或危險狀態，不用作普通終點裝飾。

## 乘車段與途經站

每段乘車卡片只承載：

- 路線號及方向；
- 首程可用時的即時 ETA；
- 本段票價；
- 本段乘坐／途經站數。

「N 個途經站」控制行位於乘車卡片外。各段預設獨立折疊，點擊整行後以 18dp Material 風格 Chevron 旋轉 180°，並在主時間線中原位插入完整站名與小圓點。展開內容不得放入巢狀卡片，也不得改變其他乘車段的展開狀態。控制行至少提供 48dp 觸控範圍，狀態只在本次頁面生命週期內保存。

## 預計時間與即時 ETA

- Citybus P2P 詳情提供的起點、各段預計上下車與最終到達時間，統一以中性文字顯示 `預計 HH:mm`。
- 首程 DATA.GOV.HK ETA 以品牌主色顯示 `即時 · 還有 N 分鐘`，可與計劃上車時刻同時存在。
- 後續乘車段若沒有可靠即時資料，只顯示 Citybus 預計上車時間。
- 暫無班次與技術故障沿用既有的結構化候車狀態，不把兩者混為一談。

## Citybus 詳情資料

`getp2pstopinroute.php` 的解析結果需要結構化保存：

- 起點與終點；
- 每段 route variant、方向、上下車站及完整途經站；
- 每段預計上下車時間及票價；
- 起點、換乘與終點步行段；
- 換乘類型（步行前往轉車站或同站換乘）；
- 最終預計到達時間。

步行段距離可為空。已確認需要前往轉車站但缺少距離時，顯示「步行前往轉車站」而不顯示數字；不得以站點座標直線距離冒充步行距離。

## 載入、失敗與生命週期

- 進入頁面後立即顯示路線結果已有的摘要，詳情內容顯示載入狀態。
- 載入失敗時保留摘要與返回操作，正文提供錯誤說明及重試。
- 部分欄位缺失時優先顯示已解析的路線和站點，隱藏缺失值，而不是讓整頁失敗。
- 頁面銷毀、實際語言改變或新請求開始後，舊回應不得覆蓋目前頁面。
- 靜態詳情快取按 P2P 查詢識別與實際語言隔離；即時 ETA 不使用同一長期快取。

## 實作方向

- 使用獨立 `RouteDetailActivity` 與 XML AppCompat／Material 版面。
- 使用單一 `RecyclerView` 表達摘要、步行段、乘車段、途經站與終點，避免巢狀捲動。
- Repository 負責請求及快取，parser 負責 Citybus HTML 假設，model／formatter 負責合計與顯示狀態，Activity／Adapter 只處理展示及互動。
- 新增與修改的 App 文案同步提供香港繁體、獨立簡體與自然英文。
- 分段顏色在淺色及深色資源中分別定義，並通過文字、路線號與節點形狀提供冗餘辨識。

## 驗證

- Parser fixture 覆蓋單程、步行換乘、同站換乘、分段距離／時間完整與缺失。
- 單元測試覆蓋詳情總步行距離、總途經站數、預計時間、票價、快取語言隔離及卡片舊語義保持。
- UI 測試覆蓋載入、失敗、重試、逐段展開／收起及返回。
- 人工驗證覆蓋繁體／簡體／英文、淺色／深色、360dp、font scale 1.0／1.3／2.0、長站名與多段換乘。
- 實作完成後執行 `./gradlew build`。
