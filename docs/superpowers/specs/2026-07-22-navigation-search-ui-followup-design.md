# 導覽、結果控制與地點編輯器後續修正設計

日期：2026-07-22

## 背景

`refine-route-ui-interactions` 已完成常用頁吸頂、底部導覽持續選中態、搜尋頁首次定位、乘車碼快捷方式及路線卡片單行站名等能力。實機截圖顯示仍有六項需要後續修正：底部導覽膠囊與標籤視覺重疊；吸頂結果控制區使用不連續的實色背景且留白仍偏多；搜尋頁與新增行程的地點編輯器幾何不一致；搜尋候選距離在部分恢復流程中消失；搜尋結果控制尚未吸頂；設定頁的桌面快捷方式請求沒有可見回饋。

本設計是上述既有設計的精確後續修正。若與 `2026-07-20-navigation-search-ui-polish-design.md` 或 `2026-07-21-route-ui-interaction-refinement-design.md` 的搜尋輸入器、底部導覽間距、結果控制區及 pinned shortcut 回饋描述衝突，以本文件為準。

## 目標

- 消除底部導覽選中膠囊與標籤的重疊，同時保留已確認的 Google Play 式選中層級。
- 讓常用與搜尋結果控制區使用相同、透明且更緊湊的吸頂組件。
- 讓新增、編輯及搜尋頁真正共用一個起終點編輯器，統一圖示、候選與距離展示。
- 讓搜尋頁在恢復已有地點後仍可非阻塞取得候選距離。
- 讓設定頁的桌面乘車碼快捷方式請求在所有結果下都有可理解的回饋。
- 在三語、深淺色、窄屏及大字體下保持相同資訊層級和觸控能力。

## 非目標

- 不改變 Citybus 地點搜尋、路線查詢、ETA、Google Geocoding 或支付工具回退語義。
- 不改變常用行程、匯入匯出或監控 session 的資料格式。
- 不修改路線結果卡片資訊結構、單行站名寬度分配或詳情彈層。
- 不新增定位、通知或桌面快捷方式的虛構運行時權限。
- 不把搜尋頁改造成地圖主導的探索頁。

## 已確認方案

### 1. 底部導覽採用 64×32dp 選中膠囊

三個 Tab 保持等寬，導覽總高度及單項觸控範圍不因選中狀態改變。

- 選中膠囊保持 `64×32dp`。
- 圖示視覺尺寸保持 `24dp`，不在選中時放大。
- 膠囊與標籤之間形成約 `5dp` 的清楚空隙。
- 選中標籤使用 `13sp Bold`；未選中標籤使用 `12sp Regular`。
- 實作可調整 Material item 的上下 padding，但驗收依實際量測的膠囊、圖示及文字位置，不只依 XML 數值。
- 一般字體下不增加導覽總高度；大字體下允許整列增高，不得讓膠囊、圖示或文字重疊。
- 深淺色只替換語意色，不改變幾何。

### 2. 常用與搜尋共用透明吸頂結果控制器

建立單一 `RouteResultControls` 版面及輕量 binder，承載五個排序按鈕、路線數量摘要和更新時間。組件只處理 View 綁定與展示，不持有查詢 repository 或排序資料。

目標尺寸：

```text
外層上 padding       2dp
排序觸控行          48dp
排序至摘要間距       4dp
摘要文字行          約 20dp
外層下 padding       2dp
-------------------------
吸頂區總高          約 76dp
首張結果卡前間距      6dp
總佔用              約 82dp
```

目前實作約為 `86dp` 吸頂區加 `12dp` 首卡前間距，合計約 `98dp`。新方案在不縮小 48dp 排序觸控行的前提下節省約 `16dp`。

- 組件背景使用透明色，直接顯示頁面 `app_page_background`；不得使用白色或固定深色 surface。
- 常用頁和搜尋頁使用同一組 padding、按鈕 style、摘要字級及首卡間距。
- 上滑時只有排序及摘要吸頂；常用行程、搜尋輸入器、保存按鈕和查詢按鈕均隨內容移出畫面。
- 沒有有效結果、查詢失敗且不保留舊結果，或輸入已使既有結果失效時，整個結果控制器隱藏。

### 3. 新增、編輯與搜尋共用 PlacePairEditor

建立 XML-backed `PlacePairEditorView` 複合 View，並由此元件統一 inflate 唯一一份起終點版面。它只負責輸入器、工具槽、候選容器、attribution、helper 及交換操作的幾何和狀態展示；既有 `PlaceInputController` 繼續負責搜尋防抖、過期請求作廢、候選選擇、距離計算和欄位錯誤。

共用幾何：

- 起點和終點各使用一個 `56dp` Material outlined input，中間基礎間距為 `8dp`。
- 起點定位操作使用 TextInputLayout 尾端位置及 `48dp` 觸控槽；定位圖示、搜尋進度共用同一槽位並保持幾何中心一致。
- 交換按鈕使用右側獨立 `48dp` 觸控區，視覺中心固定在兩個收合輸入框的垂直中線。
- 候選展開不得移動交換按鈕；交換按鈕保持可見且不與候選列重疊。
- 起點候選位於起點下方並把終點向下推；終點候選位於終點下方。
- 候選行高固定為 `52dp`，左側單行地點名稱，右側顯示定位圖示及格式化距離。
- 搜尋頁最多顯示 3 個完整候選；新增、編輯及複製頁沿用現有 3 至 6 項自適應策略。
- Google attribution、helper、無結果和錯誤只跟隨所屬欄位，不放到整個輸入器下方。

頁面差異保留在組件外：

- 行程名稱只屬於新增、編輯和複製頁，不進入 `PlacePairEditor`。
- 「儲存為常用行程」仍位於搜尋頁左側輸入欄下方，不擴展至交換按鈕區，且不成為共用組件的一部分。
- 搜尋頁及行程頁各自提供 repository、候選上限、定位回調和保存行為。

## 搜尋頁滾動架構

搜尋頁改用與常用頁相同的單一巢狀滾動模式：

```text
CoordinatorLayout
├── AppBarLayout（透明）
│   ├── 搜尋說明、PlacePairEditor、保存及查詢按鈕（可滾走）
│   └── RouteResultControls（吸頂）
└── SwipeRefreshLayout / 結果內容（主要滾動 owner）
    ├── loading / error / empty state
    └── RecyclerView 路線結果
```

- 搜尋候選仍受 IME 可見高度及最多三項限制，不把整頁改成多個互相競爭的垂直捲動容器。
- 下拉刷新只在已有有效結果、沒有候選展開且列表位於頂部時啟用。
- 查詢成功後顯示共用結果控制器；修改地點、交換或發起新查詢時立即清除舊結果資格。
- 搜尋和常用頁共用視覺組件，但各自的 `RouteQueryState`、generation 及 repository 生命週期保持獨立。

## 候選距離定位快照

`PlaceInputController` 只有收到 `CurrentLocationSnapshot` 才會顯示候選距離。搜尋頁目前只在首次／手動目前位置成功時傳入 snapshot；當 Fragment 恢復已有起點並跳過自動定位時，候選 adapter 沒有 snapshot，因此右側距離可能整欄消失。

修正流程：

1. 首次或手動目前位置成功時，照現有行為把 snapshot 同時傳給起點及終點 controller。
2. 搜尋頁恢復已有起點、使用者文字或已提交查詢而不應自動覆蓋起點時，若已有前台定位權限且系統定位開啟，靜默請求一次候選距離 snapshot。
3. 此請求只更新兩個候選 adapter，不改寫起點、不呼叫 Geocoding、不顯示欄位 loading，亦不阻塞輸入。
4. 使用者輸入、交換和查詢不需要等待此 snapshot；請求失敗時候選仍正常顯示名稱，只省略可選距離且不彈錯誤。
5. Fragment 銷毀或語言／頁面 generation 失效後，舊 callback 不得更新新 View。

## 桌面乘車碼快捷方式

設定頁的「乘車碼快捷方式」維持「請求新增到主畫面」語義，不改成直接開啟乘車碼。Android pinned shortcut 的確認由目前 launcher 負責，沒有 App 可額外申請的運行時權限。

### 狀態流程

```text
點擊設定列
├── 已固定 → 顯示「已新增至主畫面」
├── launcher 不支援 → 顯示替代操作指引
└── launcher 支援
    ├── requestPinShortcut 接受 → 提示「請在系統視窗確認新增」
    │   ├── 成功 callback → 顯示成功並刷新設定列狀態
    │   └── 使用者取消 → 無成功 callback，返回後維持未新增狀態
    └── API 返回 false／拋出異常 → 顯示可重試失敗訊息
```

- `TransitCodeShortcutManager` 提供「已固定／已發出請求／不支援／失敗」等結構化結果，不讓 `SettingsFragment` 推測平台狀態。
- pinned request 必須提供成功 callback；callback 只在真正固定成功後發出成功回饋。
- `SettingsFragment.onResume` 重新查詢 pinned 狀態，處理系統確認視窗返回和使用者從桌面移除 shortcut 的情況。
- 使用者取消不誤報失敗，因為平台不提供取消 callback。
- launcher 不支援 App 內固定時，三語文案指引使用者長按 BusIsComing 圖示，將靜態「乘車碼」快捷項拖到主畫面。
- 固定 shortcut、長按 App 圖示的靜態 shortcut 及候車通知繼續使用同一 `OPEN_TRANSIT_CODE` explicit intent 和現有支付工具回退鏈。
- 新增或修改的請求、成功、已存在、不支援及失敗文案同步提供繁體、簡體與英文。

## 錯誤、生命週期與無障礙

- 地點搜尋失敗只顯示在所屬欄位；另一欄位、已選 Place 及結果列表不受影響。
- 靜默候選距離定位失敗不顯示錯誤；使用者主動定位仍沿用既有權限、定位設定、逾時及 Geocoding 恢復流程。
- 搜尋輸入、交換、頁面隱藏和 Fragment 銷毀繼續使較舊定位、地點搜尋及路線查詢 callback 作廢。
- 排序吸頂不得遮住狀態列、鍵盤、第一張卡片或下拉刷新指示。
- 定位、交換、排序和底部導覽的觸控目標不得小於 `48dp`，並提供三語 `contentDescription`。
- 候選 row 的無障礙描述包含完整地點名稱及距離；視覺名稱可尾部省略。
- 深色模式使用相同尺寸和透明結構，文字、描邊、焦點、indicator 與 disabled 狀態使用既有 `bus_*` 語意色。

## 驗證方案

### 純邏輯與 contract 測試

- 驗證底部導覽保持 24dp 圖示、64×32dp indicator、13sp／12sp 標籤契約及穩定選中狀態。
- 驗證 `RouteResultControls` 只存在一份共用尺寸及透明背景契約，常用與搜尋均引用它。
- 驗證 `PlacePairEditor` 的 56dp 欄位、8dp 間距、48dp 工具區、52dp 候選行和候選距離內容描述。
- 驗證搜尋恢復流程會請求候選 snapshot，但不改寫已恢復起點、不呼叫 Geocoding及不阻塞輸入。
- 驗證 route query generation、保存資格及排序行為在版面重構後保持不變。
- 驗證 shortcut 已固定、請求接受、不支援、API 失敗和成功 callback 的結構化狀態。

### 裝置測試

- 切換三個 Tab 並重建 Activity，確認 indicator、圖示及標籤不重疊且導覽高度不跳動。
- 常用與搜尋各建立長結果，確認只有透明排序／摘要組件吸頂，第一張卡片前間距一致。
- 搜尋及新增行程逐一驗證起點、終點、定位、交換、候選、距離、helper、error 和 attribution 幾何一致。
- 驗證首次定位、手動定位、Tab 切換及 Activity／Fragment 重建後候選距離可用；靜默定位失敗不影響輸入。
- 在支援 pinned shortcut 的真實 launcher 驗證系統確認、成功 callback、取消、已存在及移除後狀態；不支援分支以測試替身覆蓋。

### 視覺矩陣

- 香港繁體、簡體、英文。
- 淺色、深色。
- `360dp` 與一般寬度。
- font scale `1.0／1.3／2.0`。
- 必須確認底欄無重疊、透明吸頂區不中斷頁面背景、圖示位於觸控區中心、候選距離可見、文字與圖示不互相遮擋。

### 最終驗證

實作完成後執行 OpenSpec 校驗、相關單元及 instrumentation 測試，以及：

```bash
./gradlew build
```

## 相容性與遷移

- 不需要資料庫、偏好或已保存行程遷移。
- 共用 View 取代重複 XML 時，必須同步刪除失效 view id、重複 style 和只驗證舊結構的 contract 測試。
- 既有查詢、Geocoding、保存、ETA、通知監控及支付工具啟動契約保持兼容。
