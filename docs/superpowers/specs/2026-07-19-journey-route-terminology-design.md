# 行程與路線術語設計

## 背景

BusIsComing 目前以「路線」同時表示兩種不同概念：一種是用戶保存的常用起終點配置，例如「上班」或「回家」；另一種是 Citybus 查詢返回的乘車方案，例如 `118`、`8X` 或 `85 → 106`。兩者在界面、文件和討論中容易混淆。

保存的起終點配置並不綁定任何指定巴士路線。用戶選擇同一個起終點後，可以按當時的候車時間、車費、耗時及步行距離比較多條查詢結果。因此，本設計把保存的出行意圖稱為「行程」，把查詢結果稱為「路線」。

## 概念模型

```text
常用行程「上班」
└── 名稱、起點、終點
    └── 查詢
        ├── 路線 118
        │   └── 乘車段 118
        └── 路線 85 → 106
            ├── 乘車段 85
            └── 乘車段 106
```

### 行程

「行程」是用戶保存並可重複使用的出行意圖，只包含行程名稱、起點、終點及既有使用統計。典型名稱包括「上班」「上學」「放學」和「回家」。行程不保存、不鎖定亦不代表某一條 Citybus 查詢結果。

### 路線

「路線」是以某個起點和終點查詢後得到的一個乘車方案，可以是單一路線號，例如 `118` 或 `8X`，也可以是包含換乘的組合，例如 `85 → 106`。票價、耗時、步行距離、ETA、站點預覽及路線詳情均屬於路線結果。

### 乘車段

「乘車段」是一條路線中的單段巴士服務。直達路線只有一個乘車段，換乘路線則包含多個乘車段。只有在路線詳情或需要描述換乘結構時才使用此術語，避免在一般界面增加不必要的概念負擔。

## 多語言術語基線

| 語義 | 繁體中文 | 簡體中文 | English |
| --- | --- | --- | --- |
| 保存的起終點配置 | 常用行程／行程 | 常用行程／行程 | Regular journey / journey |
| 查詢返回的乘車方案 | 路線 | 路线 | Route |
| 路線中的單段巴士服務 | 乘車段 | 乘车段 | Leg |

完整名稱用於頁面標題、首次引導和需要脫離上下文理解的位置；上下文已明確時可使用較短的「行程」。繁體使用香港實用書面語，簡體獨立審校，英文沿用自然的通勤場景用語。

## 界面文案範圍

以下用戶可見語義由「路線」調整為「行程」：

- 常用行程的新增、編輯、複製、刪除和管理。
- 行程名稱、起點和終點表單。
- 搜尋結果保存為常用行程。
- 行程資料的匯入、匯出、預覽、合併、取代、成功、失敗及私隱提示。
- 首次使用引導、空狀態、設定摘要、Toast、Dialog 和無障礙描述。
- 表達已保存配置數量、使用狀態或目前選中配置的文案。

以下用戶可見語義繼續使用「路線」：

- 查詢路線及查詢結果數量。
- 路線卡、排序、ETA、票價、耗時和步行距離。
- 路線詳情、站點、方向、換乘和通知欄監控中的乘車方案。
- Citybus 路線號及第三方返回的路線原文。

修改時須審查繁體、簡體和英文資源，不以機械字詞替換代替語義判斷。例如「查詢路線」不得改成「查詢行程」，而「新增常用路線」應改成「新增常用行程」。

## 文件沉澱

- `docs/localization-guidelines.md` 作為三語術語的權威來源，更新術語表及相關文字規則。
- `AGENTS.md` 記錄項目級長期概念邊界，要求後續功能和文件遵循相同定義。
- `README.md` 及描述目前產品行為的現行文件同步使用新術語。
- 已完成或歷史 OpenSpec change 保持原樣，不為純術語一致性批量重寫歷史 artifacts。

## 技術邊界與兼容性

本次調整只修改用戶可見文案及現行說明文件，不重命名或重構內部實現：

- 保留 `RouteConfig`、`RouteConfigRepository` 及其他 Kotlin 類別、函式、變數和檔名。
- 保留 Android string resource key，僅按語義更新各 locale 的 value。
- 保留 SQLite 表名、欄位、schema version 和既有資料。
- 保留 `.bicroutes` 副檔名、JSON schema、匯入匯出欄位和兼容行為。
- 保留 Citybus、DATA.GOV.HK 及 Google 的請求、解析、cache 和 callback 行為。
- 若自動化測試直接斷言用戶可見文字，只更新受影響的期望文案，不改變測試邏輯或產品行為。

這個邊界讓產品語言清晰，同時避免為內部命名純度引入資料遷移、協議變更或大範圍程式重構。

## 驗證

- 搜尋所有三語 string resources，逐項判斷「路線」表示行程還是查詢結果。
- 驗證常用頁、行程新增／編輯／管理、搜尋保存及匯入匯出流程的繁體、簡體和英文文案。
- 驗證查詢按鈕、結果摘要、路線卡、路線詳情和通知監控仍正確使用「路線」。
- 運行受影響的本地及 instrumentation 測試；最終運行 `./gradlew build`。
- 不要求 SQLite migration、舊 `.bicroutes` 文件遷移或外部 API 回歸測試，因為相關資料和行為不變。
