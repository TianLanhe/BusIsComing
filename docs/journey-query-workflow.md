# 行程與查詢工作流

## 領域邊界

- **行程**是使用者命名並保存的起點與終點配置，不代表固定 Citybus 路線。
- **路線**是按一個行程或臨時起終點查詢後返回的乘車方案。
- **乘車段**是一條路線中的單段巴士服務，只在詳情及換乘結構需要時使用。

內部 `RouteConfig`、`route_configs`、resource key 與 `.bicroutes` 是兼容名稱，不改變 runtime 的「行程」語義。

## 常用行程

行程保存名稱、起點／終點地點名稱及精確座標。使用者可新增、編輯、複製及刪除；名稱和起終點由 `RouteConfigValidator` 及 repository 流程校驗。

有位置 snapshot 時，常用行程按起點距離由近至遠排列；距離相同再按使用次數、最近使用時間和原 repository 次序。沒有位置或只有一個行程時保持 repository 次序。

附近行程自動選擇只在至少兩個候選時執行：

- 定位 accuracy 不存在或不大於 500 米時，選最近行程。
- accuracy 大於 500 米時，只有最近行程比第二名至少領先該 accuracy 距離才自動選擇。
- 無法可靠判斷時不猜測，保留現有／預設選擇。

同一頁面 session 內對同一行程的連續查詢、下拉刷新及配置重建後自動重查只記錄一次使用；切換到另一行程後可記錄新行程。

## 地點輸入與目前位置

新增／編輯行程和搜尋頁共用地點選擇能力：

- 文字輸入透過 Citybus `bsearch_p3.php` 取得候選，只有明確選中的 `Place` 才具有可查詢座標。
- 修改已選文字會使舊選擇失效，舊 query／語言 callback 不得重新填入。
- 起終點可交換；Google attribution 必須跟隨由 Google 解析的地址，使用者手動修改或改選 Citybus 候選後清除。
- 目前位置使用原定位座標；Google 只解析顯示名稱，不能以地址中心點替換座標。
- 權限拒絕、位置服務不可用、逾時或 geocoding 失敗使用結構化狀態，不以 mock 地址補位。

## 兩個 query owner

常用頁與搜尋頁分別持有自己的：

- 起終點或行程 id
- 是否曾提交有效查詢
- 查詢 generation／query id
- 排序欄位與方向
- RecyclerView 滾動／視口 anchor
- 本次置頂狀態
- 最近成功查詢快照與前台自動刷新狀態

兩者共享 `RouteQueryCoordinator`、repository 和結果控件，但切換 destination 不得讓一方的結果或 callback 覆蓋另一方。

### 常用查詢

使用已保存行程的精確座標提交。查詢成功、空結果及失敗均保留可理解的行程上下文；刷新使用上次成功／已提交的起終點，不重新解析名稱。

### 臨時查詢

搜尋頁只有起終點均為有效 `Place` 時才可提交。非空成功結果會把完整編輯器折疊為「本次行程」欄；使用者可重新編輯，舊結果、排序、詳情及監控仍基於上次成功快照，直到提交新查詢。

一次性查詢成功且尚未保存時可建立常用行程。保存沿用行程名稱與重複校驗；成功後同一查詢上下文只展示已保存狀態，不重複建立。

## 結果交付、排序與刷新

repository 先交付基礎路線，再增量補齊站點預覽、ETA 與地政總署 CSDI 步行結果。結果卡展示路線／換乘組合、車費、總耗時、步行距離、上下車站及候車狀態；ETA 或 CSDI 不可用時保留其他結果欄位。步行分段仍在查詢時卡片顯示短載入狀態，全部必要分段成功後使用 CSDI 合計；任一必要分段最終失敗時，整張卡回退原 Citybus 總步行距離，不混合兩個來源拼成假總量。

支援按路線、價格、總耗時、候車時間及步行距離升／降序排列。預設及普通排序只作用於未置頂區；進行中的 ETA 更新只有在目前按候車時間排序時才可相應重排未置頂結果。按步行距離排序時，已有數值的路線依方向排列，仍在查詢的路線固定在其後並保持相對次序；CSDI 漸進完成只重排未置頂區。

下拉刷新：

- 只在有有效已提交上下文且不在編輯／查詢中時啟用。
- 保留刷新前結果、排序、摘要和視口，成功後以新結果替換並更新時間。
- 失敗時保留舊結果並展示失敗反饋。
- 不增加行程使用次數。
- 新 query 或 owner 銷毀後，舊刷新／ETA／站點 callback 不得更新畫面。

前台自動刷新與手動刷新使用不同 trigger 及回饋：

- 全 App 間隔預設 1 分鐘，可在設定改為關閉、2、5 或 10 分鐘；只有目前 destination 前台可見、已有成功結果、未在編輯且沒有首次／手動查詢時才運行。
- 常用頁重用原行程 id 與精確座標，搜尋頁重用首次成功查詢保存的完整 `Place` 快照；不重新定位、不改寫表單，也不增加行程使用次數。
- 每次嘗試完成後才安排下一輪；失敗等待完整間隔並靜默保留最近成功結果／時間，返回前台時最多立即補一輪，不追趕多個錯過週期。
- 基礎路線 response 到達即可結束本輪刷新；後續 ETA、站點預覽與有效 CSDI callback 繼續在同一 query generation 漸進交付。
- 自動更新按目前排序與置頂重新投影，以刷新前第一可見路線 stable id 和 pixel offset 恢復視口；該路線消失時選擇最接近的下一張，不跳回頂部。
- 第一次在常用或搜尋頁顯示成功結果時，可出現一次性的自動刷新說明橫幅；完整展示、點擊設定或在設定頁明確選擇後才記為完成，提前離頁不吞掉提示。

## 路線詳情快照

點擊結果卡後以該 owner 最近一次成功查詢的路線、起終點及候車狀態建立 primitive launch snapshot，交給獨立 `RouteDetailActivity`。使用者若正在臨時搜尋頁修改尚未提交的文字，詳情仍屬於上一個成功快照；不把新文字或未確認地點混入既有路線。

開啟詳情不重新執行整個路線搜尋，也不增加常用行程使用次數。頁面可獨立載入可靠站點結構、Citybus 動態詳情、每段道路幾何、CSDI 步行分段、首程 ETA 及使用者主動要求的位置；配置重建保留同一快照，失敗來源只降級自己的區域。詳情自動刷新只更新身份匹配的動態時間／票價與首程 ETA，不重建結構、步行、geometry、地圖相機、展開段或選中站點。返回任何 Bottom Sheet 檔位都會退出詳情頁，回到原 query owner 的結果、排序與視口。

## 路線置頂

置頂分兩級：

- **本次置頂**：只屬於目前 owner／查詢 session，可由 SavedState 支持配置重建。
- **長期置頂**：只適用於常用行程，保存至 SQLite，重新查詢及重啟後可按 fingerprint 還原。

滑動規則：

- 未置頂向右達門檻：本次置頂。
- 本次置頂再次向右達門檻：升級為長期置頂。
- 本次或長期置頂向左達門檻：取消。
- 長期置頂向右、未置頂向左或未達門檻：回彈。
- 沒有嚴格身份或同一結果中 fingerprint 重複的路線不可置頂。

版本 1 fingerprint 由每個乘車段的公司、公開路線、route variant、bound、direction path、上車 seq 及下車 seq 組成，不包含 ETA、價格、耗時或動態站名。這讓同一服務可在動態數據更新後恢復置頂，同時避免把身份不完整的結果錯配。

投影後順序是長期置頂、本次置頂、未置頂；長期記錄按 `pinnedAt` 排列，一般排序不改變置頂區。寫入失敗時 UI 回到可解釋的本次置頂或原狀，慢速持久化結果必須按 journey id／generation 拒絕過期交付。

編輯行程時：

- 只改名稱保留長期置頂。
- 起點或終點改變時，在同一 SQLite transaction 更新行程並清除其長期置頂。
- transaction 失敗時原行程與置頂均保持不變。

## 行程匯入匯出

`.bicroutes` 版本 1 是嚴格 UTF-8 JSON：

- format：`com.golink.busiscoming.routes`
- 最多 500 個行程
- 文件上限 2 MiB
- 保存行程名稱、起終點名稱及精確座標
- 不保存資料庫 id、使用次數、最近使用時間、查詢結果、ETA、置頂、位置或監控 session

匯入先解析、校驗及預覽，再由使用者選擇：

- **合併**：以修剪後名稱、起點及終點身份跳過已有項目；文件內重複保留第一項。
- **取代**：確認後在 transaction 中刪除現有行程並匯入有效項目；失敗時現有資料保持不變。

匯出前必須提醒文件未加密且包含精確座標。讀寫使用 Android Storage Access Framework，不要求外部儲存權限；部分寫入失敗時嘗試清理不完整文件。

## 重建與失敗原則

- recreation 保存 destination、表單、有效 `Place`、排序、滾動、已提交狀態及本次置頂，不保存舊語言結果本身。
- 語言切換後曾提交的上下文以原座標重查；未提交表單不自動查詢。
- repository 返回結構化錯誤，UI 顯示目前語言資源；外部失敗不得改用 fixture 或舊語言 cache。
- 慢速資料庫、位置、Google、Citybus 或 ETA callback 必須先確認 owner、query id、語言版本和生命週期仍有效。

外部查詢與 ETA 細節見 `citybus-route-query-and-eta.md`；通用 UI／UX 原則見 `ui-style-guide.md`；精確畫面與互動場景以相應生效 OpenSpec specs 為準。
