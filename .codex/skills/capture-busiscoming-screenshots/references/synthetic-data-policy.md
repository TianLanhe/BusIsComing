# 合成資料與地名安全政策

## 預設邊界

除非使用者在本次場景契約明確覆寫，所有會出現在截圖中的動態資料都視為需合成：

- 行程名稱、起點、終點、站名、地址、地標、屋苑、學校、商場及地區。
- 路線號、variant、stop id、ETA、車程、步行距離、票價、時間戳及備註。
- 目前位置、坐標、搜尋歷史、收藏、通知內容、版本、錯誤與權限狀態。
- 姓名、電話、帳戶、裝置識別碼、token、cookie 或任何 PII／secret。

不得顯示真實或正式地名，包括縮寫、俗稱、翻譯後名稱及足以識別真實位置的地址組合。不得從使用者本機既有資料庫、SharedPreferences、通知或登入狀態取材。

## 生成與碰撞檢查

合成資料要符合產品格式與場景語意，但不能冒充真實資料：

1. 先產生語意自然的虛構名稱、路線與狀態。
2. 在 repo 對每個完整可見地名、站名、路線 identifier 做 exact-match 搜尋。
3. 對虛構地點名稱做帶引號的 exact web search，至少加上「香港」或 `Hong Kong` 上下文；命中真實地點、機構、樓盤、道路或站點就更換。
4. 對需要像真 route number 的值，與當前官方 Citybus route list 做 exact-match 碰撞檢查；有碰撞就更換。若無網路而 UI 又不能接受明顯 `DEMO`／`TEST` 值，停止並請使用者決定，不可猜測不存在。
5. 把檢查日期、方式與全部最終可見值記入 manifest。

web search 只用於碰撞檢查，真實查詢結果不得注入 App 或出現在圖片。不要把 HTTP 200 當成「不存在碰撞」；要比較實際語義內容。

## 一致性規則

- 起終點、卡片、詳情、bottom sheet、通知中的同一實體要使用相同名稱。
- ETA 分鐘、絕對時間、更新時間、步行時間與「應否出門」狀態要算術一致。
- 路線段、換乘次數、上落車站及詳情 stop sequence 要互相吻合。
- 金額、距離、版本與日期遵守 App formatter 及目前 locale，不硬編碼另一語言格式。
- 使用固定 clock／timezone 或明確基準時間，避免測試運行時間改變畫面。
- 合成錯誤要在 repository/model 邊界表達結構化 failure，不把 debug exception 文本直接展示成產品文案。

## 地圖與坐標

- 合成坐標不得送去 reverse geocoding、Citybus、ETA 或其他真實服務。
- 截圖包含 Google basemap 時，預設不可露出任何正式地名 label。選擇沒有地名標籤的中性 viewport，或請使用者對該場景作明確覆寫。
- 保留 production map component、marker、polyline 與 camera 行為；不能以手繪靜態地圖取代。
- 若真實 map provider 無法在不露出正式地名的情況下穩定渲染，將它列為阻塞，不靜默隱藏必要功能。

## 語言

預設截圖為香港繁體中文。虛構專名在其他語言場景也需人工定義自然對應，不用機器翻譯覆蓋使用者自訂名稱。若一張圖只顯示一種 locale，只注入該 locale 需要的值；同一場景矩陣則為每種 locale 設計並審校對應 fixture。

## 本次覆寫

使用者可以要求某張圖使用指定真實地點、route 或其他資料。只把覆寫套用到獲批契約列出的精確欄位，並在 manifest 顯著記錄；未被覆寫的欄位仍遵守本政策。不得把一次覆寫沉澱成 Skill 新預設。
