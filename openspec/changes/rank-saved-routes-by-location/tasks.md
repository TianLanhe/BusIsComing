## 1. 位置排序與會話使用計數契約

- [x] 1.1 新增可 JVM 單測的常用路線位置排序策略，使用 `GeoDistanceCalculator` 的整數米直線距離，並在無位置時保留 repository 的使用統計基準順序。
- [x] 1.2 實作並測試排序比較順序：距離升序、使用次數降序、最近使用時間降序，以及保留輸入的更新時間／id 穩定兜底順序。
- [x] 1.3 新增可 JVM 單測的已保存路線連續選中使用資格狀態，覆蓋首次查詢、同路線重複查詢、切換至另一保存路線後切回、同路線無操作點擊與臨時查詢不重置資格。
- [x] 1.4 擴充相關 JVM 測試，覆蓋低精度位置仍參與排序、距離相同使用統計兜底，以及既有 `NearbyRouteSelectionPolicy` 精度判定不被改變。

## 2. 主頁資料流與生命週期整合

- [x] 2.1 調整 `MainActivity` 路線載入流程：先取得 `RouteConfigRepository` 的既有使用統計基準順序，再套用本次首頁會話的成功位置快照，並同時供快捷卡與完整列表使用。
- [x] 2.2 調整自動定位成功回調：保存會話位置並重排路線；僅在手動選擇 generation 仍有效且精度規則通過時更新選中路線與 `附近` 標籤。
- [x] 2.3 保持未授權、定位關閉、失敗、超時、空結果及精度不足時的既有提示與降級；確認它們不重排、不卡住主頁、不新增定位請求，且精度不足仍保留位置排序。
- [x] 2.4 從管理頁返回、新增、編輯或刪除常用路線後，對最新資料復用本會話成功位置重排；沒有會話位置時維持使用統計排序，且不得在 `onResume` 再次自動定位。
- [x] 2.5 將目前選中的保存路線 id 與已記錄使用資格保存／還原於 `savedInstanceState`；刪除或不存在的 id 須安全忽略，冷啟動不得還原資格。
- [x] 2.6 將 `queryRoute` 的使用記錄判斷與既有 `RouteResultsRefreshPolicy` 合併：首次符合資格的保存路線查詢才呼叫 `recordUsage()`；重複查詢和下拉刷新不得更新統計，臨時查詢保持不計數。
