## Why

目前路線詳情只能展示規劃路線與裝置在地圖上的原生藍點，使用者無法直接判斷自己位於整段行程的哪個站點或哪兩站之間。新增可靠且前台限定的行程位置指示，可讓使用者在摘要及時間線中快速理解自己相對於目前候選路線的位置，同時避免把規劃頁誤解為車輛追蹤或導航。

## What Changes

- 路線詳情首次進入前台時開始取得裝置位置；已有權限時立即請求新鮮位置，未授權時先顯示可操作 Snackbar，再由使用者點擊觸發權限對話框或 App 系統設定頁。
- 以前台限定、約 `10 秒／20 米` 的省電更新節奏持續取得位置；頁面退到後台或關閉時停止，不申請背景定位、不保存位置軌跡。
- 將可靠 Citybus 站序與道路幾何、成功 CSDI 步行 paths 及同站換乘組成有序完整行程軸，僅在資料與定位精度足以判定時輸出目前站點、相鄰站點之間或步行段進度。
- 在摘要完整行動鏈上方展示固定比例的藍色 pin：巴士段按站序及相鄰站中點移動，步行段按可靠 CSDI path 累計距離比例移動。
- 在詳細時間線上展示圓心與路線軸中心精確對齊的藍色位置指示器；站點附近落在站點圓心，相鄰站點之間固定落在該軸段視覺中點。
- 將巴士時間線軸加粗並以高對比圓點展示普通站點及上下車端點；步行連接繼續使用較細的中性虛線，位置指示器仍可對齊該段。
- 首次可靠匹配乘車段時只自動展開及定位該段一次；使用者手動收合或捲動後保留其操作所有權，不持續搶奪視口。
- 對位置新鮮度、精度、離軸距離、候選歧義及跨區跳動使用明確門檻與滯回；無可靠結果時立即隱藏指示器，不使用站點直線、時間、ETA 或速度猜測。
- 提供三語、深淺色及 TalkBack 狀態描述；指示器是非操作性狀態裝飾，不攔截摘要分段或時間線操作。
- 保留 Google Maps 原生藍點及目前位置按鈕的既有地圖能力；新增指示只表達裝置相對規劃行程的位置，不標記已行經路段、不暗示巴士車輛位置或逐步導航。

## Capabilities

### New Capabilities

- `route-detail-current-position`: 定義前台定位生命週期、完整行程軸、可靠位置匹配、穩定狀態、權限與失敗處理、隱私及無障礙契約。

### Modified Capabilities

- `route-detail-bottom-sheet`: 在摘要行動鏈及詳細時間線加入位置指示、更新時間線軸與站點節點視覺，並定義自動展開、定位及使用者捲動所有權。
- `route-detail-google-map`: 將詳情頁定位由只在點擊地圖控件後請求調整為頁面進入前台即準備取得位置，並釐清行程位置指示與原生藍點、非導航邊界的關係。

## Impact

- 主要影響路線詳情 Activity／頁面狀態、摘要 formatter／presentation、RecyclerView adapter、時間線 rail／overlay、位置資料來源及新增的行程軸、匹配器與頁面 controller；現有一次性地圖目前位置能力繼續保留。
- 依賴既有 Fused Location Provider、Citybus 完整站序與已驗證 `getlinep2p.php` 幾何、成功 CSDI 步行 paths；不修改外部 API 參數、parser 原始格式、路線查詢、ETA、排序、資料庫或保存格式。
- 需要處理前台位置權限、永久拒絕、系統定位關閉、初次 fix timeout、近似位置、局部幾何／步行失敗、generation 過期及 configuration change；同類提示在單次詳情頁會話內受控去重。
- 需要新增繁體、獨立簡體及英文 runtime 資源，以及匹配器／狀態機單元測試、UI 幾何與互動測試、權限和生命週期 instrumentation 測試。
- 真實驗證須使用任務自行啟動且符合畫像的 Google APIs／Play 模擬器或設備，覆蓋模擬位置移動、前後台、權限、三語、深淺色、大字體與 TalkBack；並以真實 Citybus／CSDI／Maps 成功資料抽查匹配前提。
- 本 change 與已完成但未歸檔的 `align-settings-route-detail-polish` 保持獨立；實作及歸檔時須保留其地圖控件與路線詳情視覺契約，不以本 change 靜默取代。
